# FQ4-FINISH-001 — ROM 초기 분석 결과

- 날짜: 2026-09-13
- 계획: [FQ4-PLAN-001](../plans/001-rom-analysis.md)
- 사용자 승인: 2026-09-13 “좋아. 이제 진행해볼까?”
- 상태: **초기 분석 완료 — 정적 조사·격리 함수 검증 범위. BIOS 독립 패치 구현 및 게임/실기 검증은 미실행.**

## 1. 핵심 결론

**게임이 글리프를 BIOS에서 받는 경로가 확인되었다. 필요한 글리프를 디스크에서 RAM으로 공급하고, 해당 주소 조회 경로를 바꾸는 방향이 유력하다. BIOS 전체를 디스크에 추가하는 것만으로 이 경로가 바뀌지는 않는다.**

확인한 대표 경로는 다음과 같다.

```text
실행 파일의 2바이트 문자 코드
  → 0x800464C0에서 문자 순회
  → 0x80082C8C를 통해 BIOS B0(0x51) 호출
  → 동봉 BIOS의 글리프 주소 반환
  → 0x80046674가 30바이트 글리프를 128바이트로 변환
  → 0x800845FC(LoadImage 경로)에 사각형과 버퍼 전달
```

이 경로의 코드 `0x800464C0..0x800467C7`은 원본·241112·250826 실행 파일에서 바이트가 동일하다. 기존 한글패치는 이 대표 경로에서 BIOS 글리프 조회를 대체하지 않았다. **모든 BIOS 변경이 폰트에만 한정된다는 결론은 아니다.** 비교용 원형 BIOS와 전체 화면별 경로 검증은 아직 없다.

대표 문자열은 파일 오프셋 `0xE0158`, RAM `0x800EF958`에 있다. 원본의 `交渉中` 부분에 대응하는 패치본 코드 `8952 8EB5 917E`는 제공된 BIOS에서 시각적으로 **교·섭·중** 글리프로 복원된다. 두 패치 버전의 해당 표본은 동일하다.

| 코드 | BIOS 파일 오프셋 | 시각 해석 |
|---|---:|---|
| `8952` | `0x6AA88` | 교 |
| `8EB5` | `0x7242C` | 섭 |
| `917E` | `0x75FF0` | 중 |

글리프를 일반 CP949/UTF-8 한글로 해석한 것이 아니다. 기존 2바이트 코드 공간에 한글 글리프가 배치되어 있다. 표본 원시 바이트와 가역 토큰은 [text-map.json](../analysis/001/text-map.json)에 기록했다.

## 2. 패치 버전 차이 해결

처음에는 동봉 250826 xdelta 출력이 `patched/`와 일치하지 않았다. 사용자가 `patched/`는 **241112 xdelta 적용본**이라고 설명했고, 현재 폴더에 있는 241112 xdelta도 검증했다.

| 대상 | SHA-256 |
|---|---|
| 원본 BIN | `858f3a806cbb97d0b9dd1a43c285989ac31200959c3fbff61296780a99b81e2a` |
| 제공된 패치본 / 241112 재현 출력 | `56efd993ffae15709bf3230c27e5fab35d3461616a31a95fbc56263ca65586b3` |
| 250826 재현 출력 / 작업용 ROM | `9363cdfa247d38f5f819f5e79a25ff25ada3b2394f887726f29231da6ccbffb5` |
| 동봉 BIOS | `f8658d98e32c6a8560a832c50f74f84662e1bff98c486c6480c207a2b404b88f` |

- **241112 출력은 제공된 패치본과 전체 해시가 일치한다.** 원인 불명의 패치 실패 가설은 기각한다.
- 250826은 고정 작업용 경로에 한 번 생성하고 스트리밍 재적용 해시로 재현성을 확인했다.
- 두 패치 버전 간 차이는 실행 파일의 21개 디스크 섹터다. 실행 파일 안에서 38,413바이트가 다르며 최초·최후 차이 위치는 `0xD364C`, `0xDD434`이다. 차이를 번역 개선이나 오류 수정으로 해석하는 것은 이번에 수행하지 않았다.
- 사용자 설명은 버전 출처 확인이다. 후속 제품이 어느 버전을 지원할지 최종 선택한 것으로 간주하지 않는다. 다음 구현 계획에는 250826을 권장 기준으로 제시하되 승인 범위를 명시한다.

재현 근거: [patch-lineage.json](../analysis/001/patch-lineage.json), [reproduction.json](../analysis/001/reproduction.json).

## 3. 디스크와 변경 지도

- CUE: 단일 `MODE2/2352` 트랙, `INDEX 01 00:00:00`.
- BIN: 101,140,704바이트, 43,002 raw 섹터.
- ISO 파일 레코드: 398개. 제공된 원본/패치본 사이 파일 배치와 크기는 유지된다.
- 부트 파일: `SLPS_006.04`, 진입 주소 `0x80082BC0`.
- 실행 파일 크기: 1,075,200바이트. 2,048바이트 헤더 뒤 1,073,152바이트를 `0x80010000`에 적재하여 끝 주소는 `0x80116000`이다.
- 코드에서 이 끝 주소보다 높은 RAM의 전역 상태를 참조한다. 적재 끝 이후를 빈 공간으로 간주해 폰트를 넣으면 안 된다.

이 이미지의 확인된 좌표 변환:

```text
Form 1 사용자 데이터 위치 = LBA × 2352 + 24
연속 extent 파일의 offset f 위치
  = (extent LBA + floor(f / 2048)) × 2352 + 24 + (f % 2048)
이 실행 파일의 RAM 주소 = 0x80010000 + 파일 offset - 0x800
```

위 변환은 확인된 트랙·extent·실행 파일에 한정한다. 다른 모듈과 Form 2 파일에 그대로 적용하지 않는다.

원본 대비 제공된 241112 패치본:

| 변경 파일 | 변경 raw 섹터 수 |
|---|---:|
| `SLPS_006.04` | 48 |
| `SYS/TITLE1.GRP` | 19 |
| `SYS/TITLE2.GRP` | 19 |
| `MOV/MOV03.STR` | 8,400 |
| `MOV/MOV04.STR` | 4,223 |

총 12,709섹터, 23,728,296바이트가 다르다. 변경 섹터는 모두 위 파일의 extent에 귀속되며 미귀속 변경 섹터는 없다. 원본 Form 1/2 수는 40,654/2,348, 제공된 패치본은 40,653/2,349이다. `MOV03.STR`의 마지막 섹터 LBA 18,429가 Form 1에서 Form 2로 바뀐다. 동영상 내용·정상 재생과 EDC/ECC 전체 유효성은 검증하지 않았다.

## 4. 폰트·텍스트 근거와 한계

확인한 함수는 두 바이트를 `(첫 바이트 << 8) | 둘째 바이트`로 합쳐 BIOS에 전달한다. 문자 순회에서는 `00` 및 `02`가 종료 조건이며, 일부 단일 바이트는 이 글리프 적재 경로에서 건너뛴다. 이를 전체 스크립트 제어 코드 명세로 확대하지 않는다.

글리프 변환 함수는 16×15 1bpp에 해당하는 30바이트를 읽어 4bpp 16×16 버퍼 128바이트로 변환하고 마지막 행을 0으로 채운다. 동봉 BIOS 주소 계산 함수와 게임 변환 함수를 Unicorn에서 격리 실행했다.

- 유효 코드 6개: 반환 주소 확인 및 독립적인 비트 전개 결과와 128바이트 일치.
- 무효 코드 `0000`, `FFFF`: `FFFFFFFF` 반환 확인.
- 표본 문자열 3개 버전: 토큰화 후 원시 바이트 왕복 일치.
- [정적 글리프 복원 이미지](../../../work/fq4/001/glyph-sample.png)는 실제 게임 화면 캡처가 아니다.
- BIOS 파일 일부를 RAM으로 옮기는 실험 배치는 내부 호출·테이블 위치로 추론하여 명시적으로 설정했다. 실제 BIOS 부팅을 재현한 것이 아니다.

초기 적재 좌표는 `(512, 416)`, 1글리프 전송 사각형은 VRAM word 기준 `4×16`이다. 반복문의 좌표만 계산하면 초기화 모드에서 192슬롯이다. 여러 번 이어 붙이는 호출과 다른 VRAM 자산의 소비는 검증하지 않아 실제 전체 표시 용량으로 확정하지 않는다.

분량 상태는 **하한**이다. 확인된 대표 문자열 1개와 실행 파일 내 글리프 적재 함수의 직접 JAL 후보 34곳을 확보했다. 34곳은 문자열 수가 아니다. 전체 대사·이름·메뉴·그래픽 문자의 모집단, 전체 한글 글리프 종류 수, 간접 호출은 미확정이다.

## 5. 개선 방향 비교

| 후보 | 필요한 변경 | 판단 |
|---|---|---|
| BIOS 전체 512 KiB를 디스크에 포함 | 데이터 적재, 글리프 주소 재지정 또는 별도 실행 경로 필요 | 파일 추가만으로 해결되지 않으며 불필요한 BIOS 영역까지 포함하므로 우선순위 낮음 |
| 필요한 글리프와 코드 매핑을 디스크에 포함 | RAM 상주 위치 확보, 초기 적재, BIOS 조회 대신 RAM 글리프 주소 반환 | **우선 권장**. 확인된 변환·VRAM 전송 경로를 재사용할 가능성이 높음 |
| 화면별 글리프만 수시 적재 | 화면별 코드 집합·캐시·CD 상태 관리 | 상주 메모리가 부족할 때 검토할 조건부 대안 |

동봉 BIOS의 확인된 두 글리프 시작 위치는 `0x66000`, `0x69D68`이다. 기술 자료의 뒤쪽 문자셋 경계까지 단순히 포함하는 후보 구간은 약 102 KiB 규모지만, 실제 이 게임에 필요한 글리프 수·정확한 포함 범위·RAM 여유는 아직 산정하지 않았다. 후속 계획에서는 전체 BIOS 포함 여부보다 **필요 데이터 범위와 안정적인 상주 RAM 확보**를 먼저 검증해야 한다.

## 6. 미해결 위험과 다음 검증

| ID | 미해결 사항과 영향 | 다음 판별 작업 |
|---|---|---|
| R01 | 모든 표시 경로가 같은 BIOS 글리프 경로를 사용하는지 미확정 | 34개 직접 호출 후보와 간접·별도 렌더러를 분류하고 대표 화면에 연결 |
| R02 | 글리프 상주 RAM·디스크 배치 미확정 | 힙·BSS·오버레이·버퍼 수명과 코드 집합 측정. 빈 바이트만으로 공간 채택 금지 |
| R03 | 원형 BIOS와의 차이 범위 미확정 | 사용 가능한 정상 BIOS와 비교하고 필요한 코드별 반환 값·글리프를 대조 |
| R04 | 실제 GPU 표시·화면 전환 미검증 | 별도 한글 BIOS 사용/미사용 기준 화면 및 디스크 글리프 PoC를 동일 경로에서 비교 |
| R05 | PS1 실기 사용 환경과 동작 미검증 | 후속 계획에서 기종·부팅 수단·진입 절차 확정 후 정상 플레이 관찰 |
| R06 | 섹터 보호 필드와 로더 제약 미검증 | 쓰기 전 무변경 왕복, 예상 쓰기 범위, 섹터별 EDC/ECC·LBA 참조 검증 |
| R07 | 전체 글리프 수·텍스트 분량 미확정 | 소비자 기준 열거로 정확값/하한을 갱신. 인코딩 누락은 후속 빌드 실패로 처리 |
| R08 | 동봉 BIOS 자산의 재배포 조건 미확정 | 배포 계획 시 권한 확인 또는 사용자 제공 BIOS로부터 로컬 추출하는 빌드 경계 검토 |

권장 후속 작업은 **250826 기준 BIOS 글리프 대체 PoC 계획 작성**이다. 필수 PoC는 별도 한글 BIOS 없이 디스크 자산을 실제 화면에서 소비하는 경로 및 화면 전환 후 유지 여부다. 수시 CD 적재 방식은 상주 메모리 부족이 확인될 때만 조건부 PoC로 진행한다. 이번 조사에서는 ROM 변경 PoC를 수행하지 않았다.

## 7. 완료 기준별 판정

| 계획 기준 | 판정 |
|---|---|
| 1. 입력·구조·후속 수정 경계 | 확인. 후속 빌드 지원 프로필 및 RAM 배치는 아직 미채택 |
| 2. 패치 재현 | 두 xdelta 모두 검증. 241112는 제공 패치본과 일치 |
| 3. 변경 영역 귀속 | 변경 섹터 전부 파일 extent에 귀속 |
| 4. 대표 텍스트 가역 해석·소비 경로 | 정적 코드와 격리 변환 함수로 확인. 실제 GPU/화면은 미검증 |
| 5. 초기 분량과 미조사 범위 | 대표 표본 하한으로 기록, 전체 분량 미확정 |
| 6. 위험별 다음 진단 | R01–R08에 기록 |
| 7. 입력 보존·완료 문서 | 입력 전체 해시 일치, 이 문서 작성 |
| 8. BIOS 의존 원인·개선 후보 | 대표 경로 확인, RAM 글리프 공급 방식 우선 권장 |

초기 분석이 확보한 것은 후속 구현 방향을 결정할 근거다. BIOS 독립성·실기 지원·전체 번역 품질·배포 가능성의 완료 판정은 아니다. 실행 환경은 PATH에서 에뮬레이터를 발견하지 못했고 이번 스레드에 구동 설정·실기 세션이 제공되지 않아 게임 실행 관찰을 수행하지 않았다. 시스템 전체에 에뮬레이터가 없다고 단정하지 않는다.
