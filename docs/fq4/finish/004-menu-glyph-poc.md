# FQ4-FINISH-004 — 지도 메뉴 글리프 조사 및 일반 BIOS PoC 결과

- 날짜: 2026-09-13
- 계획: [FQ4-PLAN-004](../plans/004-menu-glyph-poc.md)
- 사용자 승인: 2026-09-13 “진행하자”
- 사용자 화면 확인: 2026-09-13 “응 잘나온다. 시간경과, 부대이동, 탐색.”
- 기술 판정: **통과 — 일반 BIOS에서 세 메뉴 문자열 표시 확인**

## 1. 결과

`시간경과`, `부대이동`, `탐색`의 실제 코드열과 실행 파일 위치를 확정했다. 중복을 제거한 10개 메뉴 글리프에 기존 `교섭중` 3개를 더해 총 13개 글리프를 ROM에 넣었고, 테이블 조회 방식으로 기존 훅을 확장했다.

일반 BIOS의 실제 DuckStation 런타임에서 13개 코드가 모두 게임 조회 훅, 기존 변환 함수와 `LoadImage`까지 도달했다. 각 GPU 업로드 버퍼는 동봉 한글 BIOS 글리프의 격리 변환 기준과 일치했다.

사용자가 일반 BIOS로 갱신된 지도 메뉴를 직접 확인했으며 `시간경과`, `부대이동`, `탐색`이 정상 표시된다고 보고했다. 메뉴 종료·재진입에 관한 별도 관찰 기록은 없으므로 장시간 상태 수명은 후속 회귀 검사 항목으로 남긴다.

## 2. 대상 문자열

| 문자열 | 코드열 | 실행 파일 위치 |
|---|---|---:|
| `시간경과` | `8F62 88A1 88E4 88F8` | `0x12D0` |
| `부대이동` | `8DCC 8AE9 90CA 8B5E` | `0x12DE` |
| `탐색` | `935C 8E96` | `0x12EC`, `0xD5D1B` |

필요 글리프는 `시`, `간`, `경`, `과`, `부`, `대`, `이`, `동`, `탐`, `색`이다. 코드, 동봉 BIOS 오프셋과 30바이트 글리프 해시는 [menu-glyphs.json](../analysis/004/menu-glyphs.json)에 기록했다.

## 3. 구현과 결함 수정

| 항목 | 값 |
|---|---|
| 조회 코드 | `0x800ECC40`, 116바이트 |
| 코드 테이블 | `0x800ECCC0`, 52바이트 |
| 글리프 | `0x800ECD00`, 390바이트 |
| 등록 코드 | 기존 3개 + 메뉴 10개 = 13개 |
| 일반 코드 | 원래 BIOS `B0(51h)`로 폴백 |

첫 구현은 `lhu` 뒤에 로드 지연 슬롯을 두지 않아 실제 R3000A 런타임에서 잘못된 데이터가 업로드됐다. 두 load 뒤에 `nop`을 추가하고 검증기에 load-delay 감사를 넣었다. 수정 후 13개 업로드 해시가 모두 기준과 일치했다.

## 6. 사용자 화면 확인 결과

사용자가 현재 `current.bin`을 일반 BIOS로 실행하여 `시간경과`, `부대이동`, `탐색`이 정상 표시되는 것을 확인했다. 새 캡처 파일은 없으므로 판정 근거는 사용자 관찰 진술이며, 선행 한글 BIOS 기준 화면은 `work/fq4/003/korean-bios-menu.png`다.

## 7. 보존과 다음 단계

- 원본 게임, BIOS, xdelta와 사용자 스크린샷은 수정하지 않았다.
- 모든 분석·빌드·검증 스크립트는 `tools/scripts/`에 작성했다.
- 작업 ROM은 `current.bin` 한 벌만 유지했다.
- 런타임 검사 후 DuckStation을 종료했다.
- 전체 글리프 구조나 배포 패치로 확장하지 않았다.

사용자 화면 검증이 통과하면 다음 계획에서 전체 250826 텍스트에 필요한 글리프 집합과 제품용 저장·RAM 상주 구조를 조사할 수 있다.
