- 날짜: 2026-09-13
- 계획: [FQ4-PLAN-002](../plans/002-bios-independent-font-poc.md)
- 사용자 승인: 2026-09-13 “좋아 다음 계획 진행하자”
- DuckStation 최초 실행 승인: 2026-09-13 “그래 진행해봐”
- 기준: 250826 한글패치 적용본
- 기술 판정: **부분 통과 — 일반 BIOS 부팅과 실제 게임 GPU 업로드 경로 통과, 화면 가시성 미확인**

## 1. 결과

ROM 안의 최소 한글 글리프를 반환하는 훅을 만들었고 정적 이미지 검증과 MIPS 격리 실행은 통과했다. 세 한글 코드가 동봉 한글 BIOS와 동일한 30바이트 글리프를 ROM 내부에서 선택하며, 게임의 기존 16×15 1bpp → 16×16 4bpp 변환 결과도 기준과 바이트 단위로 일치한다.

사용자가 추가한 일반 `scph1001.bin`으로 DuckStation에서 PoC ROM을 부팅했다. 정상 실행 중 게임이 패치 훅에 일반 코드 `8140`을 전달하는 것을 확인했고, CPU 상태를 명시적으로 개입한 런타임 검사에서는 대표 세 코드가 실제 게임 조회·변환 함수와 `LoadImage` 호출까지 도달했다. 세 GPU 업로드 버퍼는 동봉 한글 BIOS 기준 해시와 모두 일치했다.

화면 자동화 연결이 작동하지 않아 최종 픽셀을 캡처하지 못했고, 대표 문자열까지 정상 플레이 입력만으로 도달하는 절차도 확인하지 못했다. 따라서 계획의 전체 PoC는 여전히 부분 통과로 판정한다.

```text
패치 문자열 코드
  ├─ 8952 / 8EB5 / 917E → ROM 내부 “교/섭/중” 글리프
  └─ 그 외 코드          → 원래 BIOS B0(51h)
       ↓
기존 게임 변환 함수 0x80046674
       ↓
기존 LoadImage 경로
```

## 2. 구현 내용

250826 실행 파일의 `Krom2RawAdd` 래퍼 `0x80082C8C` 첫 8바이트를 `0x800ECC40`의 최소 조회 코드로 향하는 점프로 바꿨다.

| 코드 | 문자 | 반환 RAM 주소 | 글리프 크기 | 격리 결과 |
|---|---|---:|---:|---|
| `8952` | 교 | `0x800ECD00` | 30바이트 | 기준 변환 해시 일치 |
| `8EB5` | 섭 | `0x800ECD1E` | 30바이트 | 기준 변환 해시 일치 |
| `917E` | 중 | `0x800ECD3C` | 30바이트 | 기준 변환 해시 일치 |
| `8140` | 일반 BIOS 코드 표본 | BIOS `B0(51h)` 폴백 | 해당 없음 | 입력·함수 번호 보존 |

PoC 조회 코드는 128바이트이고 글리프는 총 90바이트다. 모두 실행 파일에 이미 적재되는 주소에 있으므로 새 CD 읽기, 신규 파일, 파일 크기 증가와 별도 RAM 복사는 없다. 이는 최소 PoC에서 저장 → RAM 상주 경계를 단순화한다.

선택한 영역은 250826에서 0으로 채워져 있고 제한된 정적 참조 조사에서 직접 참조가 없었다. 전체 간접·범위 소비와 런타임 접근은 확인하지 못했으므로 제품용 안전 공간으로 승인하지 않는다. 전체 폰트는 이 영역에 들어가지 않으며 후속 설계에서 별도 저장·상주 방식을 결정해야 한다.

## 5. 일반 BIOS 추가 검증

공식 DuckStation portable 0.1.11894를 `work/fq4/tools/duckstation/`에 준비했다. Windows Computer Use는 최초 연결, 재시도, 세션 초기화 후 재시도 모두 `native pipe is unavailable`로 실패했다. 명령행 실행은 가능하지만 대표 화면까지 입력하고 화면을 캡처할 자동 관찰 수단이 없었다.

추가된 `original/scph1001.bin`은 524,288바이트이며 SHA-256은 `71af94d1e47a68c11e8fdb9f8368040601514a42a5a399cda48c7d3bff1e99d3`이다. 동봉 한글 BIOS와 ROM 버전 문자열이 `System ROM Version 2.2 12/04/95 A`로 같고, 차이는 `0x69D68..0x7B0CB` 구간의 67,422바이트에 한정된다. 일반 BIOS는 portable DuckStation의 BIOS 폴더에 한 번 복사해 후속 검사에서도 같은 파일을 재사용한다.

DuckStation은 이를 `SCPH-1001 ... (v2.2 12-04-95 A)`, NTSC-U BIOS로 기록하고 일본판 `SLPS-00604`를 부팅했다. 지역 불일치 경고는 있었지만 시스템 부팅과 커널 초기화는 완료됐다. 정상 실행 중 일반 코드 `8140`이 실제 패치 훅에 도달했다.

대표 화면의 입력 절차를 모르는 상태에서는 GDB로 CPU 상태를 개입해 실제 렌더러 `0x800464C0`에 세 코드를 전달했다. 각 코드는 훅 `0x80082C8C`과 `LoadImage` `0x800845FC`를 거쳤으며 업로드 버퍼 해시가 정적 기준과 일치했다. CPU 레지스터와 임시 RAM은 복원했지만 GPU·전역 상태는 복원하지 않아 검사 뒤 DuckStation PID 13124를 종료했다. 이 증거는 최종 화면 픽셀이나 정상 플레이 도달성을 대신하지 않는다.

## 6. 다음 권장 방향

우선 새 구현을 추가하지 말고 현재 PoC의 런타임 검증을 완료하는 것이 좋다. 다음 작업은 별도 계획에서 다음 두 단계로 나눈다.

- 현재 일반 BIOS 환경에서 대표 화면의 “교섭중” 표시, 주변 UI, 종료·재진입을 직접 관찰한다.
- 통과한 뒤 전체 250826 텍스트의 사용 글리프와 렌더러 경로를 열거하여 전체 폰트의 저장·RAM 상주 설계를 선택한다.

현재 218바이트 규모의 실행 파일 내 PoC 배치는 전체 폰트 용량 문제를 해결하지 않는다. 런타임 통과 전에는 대규모 폰트 이관이나 제품 패치 도구로 확장하지 않는다.

## 7. 보존과 정리

- 원본 게임·일반 BIOS·241112 패치본·xdelta·동봉 BIOS는 수정되지 않았다.
- 분석·빌드·검증 코드는 `tools/scripts/`에 작성했다.
- 전체 작업용 ROM은 `work/fq4/rom/current.bin` 하나뿐이다.
- DuckStation 다운로드 ZIP 72,669,228바이트는 압축 해제 후 삭제했으며 복구할 필요가 없는 재다운로드 가능한 파일이다.
- portable DuckStation은 후속 런타임 검증을 위해 `work/`에 남겼다.
- 배포용 xdelta, 전체 BIOS 또는 별도 전체 ROM 복사본은 생성하지 않았다.
