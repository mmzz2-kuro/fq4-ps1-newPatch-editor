- 작성일: 2026-09-13

## 1. 목적

지도 메뉴에서 쉽게 재현할 수 있는 `시간경과`, `부대이동`, `탐색`의 실제 패치 코드열과 렌더링 경로를 찾는다. 세 문자열에 필요한 중복 제거 글리프를 동봉 한글 BIOS에서 식별하고, 현재 BIOS 독립 조회 PoC를 안전하게 확장할 수 있는지 용량과 배치를 검증한다.

확장이 가능하면 같은 작업 ROM에 메뉴 전용 PoC를 적용하고 일반 BIOS에서 세 문자열이 ROM 내장 글리프로 변환·업로드되는 것까지 검증한다. 사용자가 촬영한 한글 BIOS 화면을 시각 기준으로 사용한다.

## 2. 승인 범위

- 250826 패치본과 현재 PoC에서 대상 문자열의 저장 위치와 실제 코드열을 찾는다.
- 코드열의 종단, 제어 코드, 문자열 참조와 메뉴 렌더러 호출 경로를 확인한다.
- 대상 문자열에 필요한 글리프 집합을 중복 제거하여 확정한다.
- 각 코드의 동봉 한글 BIOS 글리프 주소와 30바이트 원본 글리프를 검증한다.
- 현재 PoC의 코드·데이터 공간으로 메뉴 글리프를 수용할 수 있는지 계산한다.
- 안전한 범위 안에서 가능하면 기존 조회 훅을 확장해 같은 `current.bin`에 적용한다.
- 정적 검사, MIPS 격리 실행과 실제 DuckStation 런타임 호출 검사를 수행한다.
- 화면 캡처가 가능하면 일반 BIOS 메뉴 화면을 한글 BIOS 기준 화면과 비교한다.
- 결과를 `docs/fq4/finish/004-menu-glyph-poc.md`에 기록한다.

전체 250826 문자 집합, 제품용 전체 폰트 저장 구조, 배포용 xdelta, 사용자용 GUI와 실기 검증은 이번 범위에 포함하지 않는다.

## 3. 보존 및 용량 규칙

- `original/`, `patched/`, `korean-patch/`는 읽기 전용으로 취급하며 수정·이동·삭제하지 않는다.
- 일반 BIOS와 동봉 한글 BIOS는 분석 입력으로만 사용한다. 배포 산출물에 BIOS 전체를 포함하지 않는다.
- 전체 작업용 ROM은 `work/fq4/rom/current.bin` 한 벌만 사용한다. 새 BIN·ISO·IMG를 만들지 않는다.
- 빌드 시 기준 복원이 필요하면 기존 빌드 스크립트가 같은 `current.bin`을 초기화하고 다시 쓰게 한다.
- 작업 실패 시 부분 적용 ROM을 남기지 않는다. 모든 사전 조건을 확인한 뒤 한 번에 갱신하거나 원래 PoC 상태를 유지한다.
- 분석·변환·빌드·검증 스크립트는 `tools/scripts/`에 작성한다.
- 사용자용 GUI는 만들지 않는다.
- 캡처, 로그와 추출 글리프는 `work/fq4/004/`에 필요한 최소량만 보관한다.

## 5. 실행 절차

### A. 대상 문자열 위치와 코드열 확정

1. 250826 패치본의 ISO 파일과 raw 섹터에서 세 문자열 후보를 검색한다.
2. 한글 BIOS 글리프 인덱스와 역매핑하여 가능한 2바이트 코드열을 생성한다.
3. 후보 코드열을 패치본에서 검색하고 앞뒤 바이트, 문자열 종단과 제어 코드를 함께 기록한다.
4. 문자열을 가리키는 포인터, 메뉴 항목 테이블 또는 로더 참조를 찾는다.
5. 동일 코드열이 다른 화면에서도 사용되는지 조사하여 메뉴 전용 여부와 공유 범위를 구분한다.

문자 모양만 보고 코드를 추정하지 않는다. 저장 바이트, BIOS 글리프와 실제 렌더러 입력 중 최소 두 근거가 일치해야 확정한다.

### B. 필요 글리프 집합 생성

1. 세 문자열의 표시 문자에서 중복을 제거한다.
2. 각 문자에 실제 패치 코드, 동봉 BIOS 글리프 오프셋, 30바이트 해시를 연결한다.
3. 공백, 구두점이나 제어 코드가 포함되면 글리프와 분리한다.
4. 추출된 30바이트 글리프를 기존 게임 변환 함수에 입력해 128바이트 결과를 생성한다.
5. 동봉 한글 BIOS를 사용하는 기준 결과와 바이트 단위로 비교한다.

예상 중복 제거 문자 후보는 `시`, `간`, `경`, `과`, `부`, `대`, `이`, `동`, `탐`, `색`이다. 실제 코드열 분석으로 최종 확정한다.

### C. PoC 수용 가능성 검토

1. 기존 조회 코드 128바이트와 “교섭중” 글리프 90바이트의 배치를 다시 감사한다.
2. 메뉴 글리프 수 × 30바이트와 조회 테이블·코드 증가량을 계산한다.
3. 현재 개발용 0 영역에서 직접·간접 참조, 로더 소비와 덮어쓰기 가능성을 재검토한다.
4. 실행 파일 내부에 안전 근거가 부족하거나 용량이 모자라면 구현하지 않고 실패·미해결로 기록한다.
5. 가능하면 선형 비교 나열보다 코드→글리프 테이블 조회를 사용해 이후 확장 가능성과 코드 크기를 함께 평가한다.

이번 PoC의 빈 공간은 제품용으로 승인하지 않는다. 메뉴 검증을 위한 임시 개발 배치로만 사용한다.

### D. 빌드

1. 기존 `build_bios_independent_poc.py`를 확장하거나 새 메뉴 PoC 빌더를 `tools/scripts/`에 작성한다.
2. 빌더는 모든 입력 해시, 원래 명령열, 배치 범위와 0 영역을 먼저 확인한다.
3. 같은 `work/fq4/rom/current.bin`을 250826 기준에서 재구성한 뒤 메뉴 PoC를 한 번에 적용한다.
4. 실행 파일 사용자 데이터 변경 뒤 해당 Mode 2 Form 1 섹터의 EDC와 P/Q ECC를 다시 계산한다.
5. 예상 쓰기 목록에 없는 바이트 차이가 하나라도 있으면 빌드를 실패시킨다.

### E. 정적·격리 검증

- 모든 대상 코드가 올바른 ROM 글리프 RAM 주소를 반환하는지 확인한다.
- 대상 밖 일반 코드가 BIOS `B0(51h)` 폴백으로 전달되는지 확인한다.
- 모든 글리프 변환 결과가 동봉 한글 BIOS 기준 128바이트와 일치하는지 확인한다.
- 훅 ABI, 저장 레지스터, 분기, 지연 슬롯과 반환 경로를 역어셈블 및 격리 실행으로 검사한다.
- 수정 섹터의 EDC/ECC, ISO 파일 구조, ROM 크기와 CUE를 확인한다.
- 최종 ROM 전체 diff를 예상 쓰기 목록과 대조한다.

### F. 일반 BIOS 런타임 검증

1. 일반 BIOS로 갱신된 `current.cue`를 새 부팅한다.
2. 실제 게임이 대상 코드로 조회 훅과 `LoadImage` 경로에 도달하는지 기록한다.
3. 가능한 경우 사용자가 재현한 지도 메뉴에 진입하여 스크린샷을 촬영한다.
4. `시간경과`, `부대이동`, `탐색`의 형태, 간격, 기준선과 주변 UI를 한글 BIOS 기준 화면과 비교한다.
5. 메뉴를 닫고 다시 열어 글리프 재현과 VRAM 상태를 확인한다.

화면 자동화가 다시 실패하면 실제 런타임 훅·업로드 근거와 사용자 캡처 필요 항목을 분리하여 기록한다. 상태 개입으로 만든 호출은 정상 플레이 도달 증거로 사용하지 않는다.

### G. 정리와 입력 보존 확인

- 에뮬레이터를 종료한다.
- 원본 게임, BIOS, xdelta와 작업 ROM의 종료 해시를 기록한다.
- `work/fq4/rom/`의 전체 ROM BIN이 `current.bin` 한 벌인지 확인한다.
- 중간 전체 ROM, 임시 패치 이미지와 중복 캡처를 남기지 않는다.

## 6. 판정 기준

### 통과

다음 조건을 모두 만족해야 한다.

1. 세 문자열의 저장 코드열, 참조와 렌더러 입력이 재현 가능하게 확정된다.
2. 필요한 모든 글리프가 코드·오프셋·해시와 연결된다.
3. 메뉴 PoC의 배치와 모든 변경 바이트가 설명된다.
4. 정적 검사, MIPS 격리 실행, EDC/ECC와 ISO 구조 검사가 통과한다.
5. 일반 BIOS 런타임에서 대상 글리프가 실제 조회·변환·업로드 경로를 통과한다.
6. 일반 BIOS 메뉴 화면에서 세 문자열이 올바르게 표시되고 주변 UI가 유지된다.
7. 메뉴 종료·재진입에서도 같은 결과가 재현된다.
8. 입력 파일이 보존되고 작업 ROM이 한 벌만 남는다.

### 부분 통과

정적·격리·실제 런타임 업로드가 통과했지만 화면 관찰 수단이 없으면 부분 통과로 기록한다. 화면 표시 성공을 추정하지 않는다.

### 실패

- 코드열이나 글리프 매핑이 둘 이상의 근거로 확정되지 않는다.
- 안전한 임시 배치 공간이나 필요한 용량을 확보하지 못한다.
- 예상 밖 ROM 변경, EDC/ECC 오류 또는 ISO 구조 손상이 발생한다.
- 일반 BIOS에서 대상 글리프가 잘못 변환·업로드되거나 게임 진행을 손상한다.
- 최종 화면에서 글자 또는 주변 UI가 잘못 표시된다.

실패하면 최초 실패 경계와 가능한 대체 저장·조회 설계만 제안하고 이번 승인으로 추가 구현하지 않는다.

## 8. 중단 조건

다음 상황에서는 ROM 구현 전에 중단하고 완료 문서에 근거를 남긴다.

- 대상 문자열의 코드열이나 참조가 유일하게 식별되지 않는다.
- 현재 PoC 영역의 런타임 안전성을 더 이상 지지할 수 없다.
- 메뉴 글리프가 다른 렌더러나 별도 자산 경로를 사용한다.
- 필요한 변경이 실행 파일 내 최소 PoC를 넘어 신규 파일, 대규모 재배치 또는 별도 로더 설계가 된다.
- 일반 BIOS와 한글 BIOS 비교에서 글리프 이외의 동작 차이가 발견된다.
