# FQ4-PLAN-017 — PS1 캐릭터 세이브 에디터 제작 계획

- 작성일: 2026-09-14
- 상태: **구현 및 정적 검증 완료 — 게임 내 사용자 검증 대기**
- 대상 게임: PS1 `SLPS-00604` 퍼스트퀸4
- 기준 메모리카드: `memcard/First Queen IV - Varcia Senki (Japan)_1.mcd`
- 참고 상태 저장: `savestates/SLPS-00604_1.sav`, `savestates/SLPS-00604_resume.sav`
- 참고 DOS 자료: `dos-save/FQ4GD.*`, `dos-save/editor/FQ4Edit.exe`
- 사용자용 도구 예정: `tools/FQ4SaveEditor/`
- 완료 문서 예정: `docs/fq4/finish/017-ps1-save-editor.md`

## 1. 목적

PS1판 퍼스트퀸4의 메모리카드 세이브에서 캐릭터의 영구 데이터를 읽고 수정하는 Windows GUI 에디터를 제작한다.

첫 지원 범위는 다음과 같다.

- 메모리카드에 저장된 FQ4 세이브 슬롯 검색
- 슬롯별 캐릭터 목록 표시
- 특정 캐릭터 선택
- 검증된 캐릭터 능력치 수정
- 캐릭터 종족 변경
- 게임이 인정하는 체크섬과 디렉터리 상태를 유지한 새 메모리카드 생성

치트처럼 실행 중 RAM 값을 고정하지 않고, 게임의 정상 저장 구조에 영구 반영하는 것을 목표로 한다.

## 2. 현재 확인된 입력 구조

기준 `.mcd`는 헤더가 `MC`인 131,072바이트 표준 PS1 메모리카드다. FQ4 세이브가 두 개 들어 있다.

| 저장 이름 | 시작 블록 | 사용량 | 블록 체인 |
|---|---:|---:|---|
| `BISLPS-00604-1` | 1 | 32,768바이트 | 1→2→3→4 |
| `BISLPS-00604-2` | 5 | 32,768바이트 | 5→6→7→8 |

두 DuckStation 상태 저장은 `DUCCT` 컨테이너이고 게임 ID가 `SLPS-00604`로 일치한다. 런타임 RAM에서 캐릭터 구조를 찾는 보조 자료로 사용한다.

DOS 세이브와 `FQ4Edit.exe`는 골드·아이템·캐릭터 편집 기능과 필드 명칭을 참고하는 자료로만 사용한다. PS1판과 오프셋이나 체크섬이 같다고 가정하지 않는다.

## 3. 분석 단계

### A. 메모리카드와 게임 세이브 추출

- 15개 PS1 디렉터리 entry와 블록 체인을 파싱한다.
- `BISLPS-00604-*`의 32KiB payload를 논리 순서대로 추출한다.
- PS1 디렉터리 XOR 체크섬과 게임 payload 내부 체크섬 후보를 구분한다.
- 슬롯 번호, 표시 제목, 아이콘 frame과 실제 게임 데이터 경계를 기록한다.
- 빈 슬롯, 손상된 체인, 다른 게임 데이터와 함께 있는 카드도 안전하게 거부하거나 보존할 수 있게 한다.

### B. 캐릭터 record 구조 규명

- 두 PS1 세이브 payload의 반복 구조와 차이 구간을 비교한다.
- 캐릭터 ID, 이름/표시 ID, 종족, 소속 부대, 레벨과 능력치 후보를 찾는다.
- DuckStation 상태 저장 또는 런타임 RAM에서 현재 화면에 보이는 값을 검색해 후보를 교차 검증한다.
- ROM 실행 코드의 저장·불러오기·캐릭터 초기화 함수를 추적해 필드 폭, 부호, 범위와 record stride를 확정한다.
- DOS 에디터의 354유닛 구성과 항목명을 참고하되 PS1 데이터로 독립 검증한다.

### C. 체크섬과 파생값 규명

- 한 필드만 바꾼 통제 세이브가 필요하면 기존 메모리카드의 복사본에서 수행한다.
- 저장 전후 차이로 payload 체크섬 위치와 알고리즘을 찾는다.
- 능력치 총합, 최대 HP와 현재 HP처럼 함께 갱신해야 하는 파생 필드를 확인한다.
- 종족 변경 시 그래픽 ID, 이동 방식, 직업 또는 장비 제한 같은 연동 필드가 있는지 확인한다.
- 종족 ID만 바꿔도 되는지, 캐릭터별 허용 목록이나 초기화 함수 호출이 필요한지 판정한다.

## 4. 편집 기능

분석으로 의미와 안전 범위가 확인된 필드만 GUI에서 활성화한다.

### 필수 기능

- `.mcd` 파일 열기
- FQ4 슬롯 1/2 자동 검색과 선택
- 캐릭터를 ID·이름·소속 부대 기준으로 검색 및 선택
- 종족을 ID와 표시명으로 선택
- 확인된 능력치를 숫자로 편집
- 변경 전후 값을 표 형태로 확인
- 다른 이름의 `.mcd`로 저장
- 저장 결과를 다시 읽어 구조·체크섬·변경 범위를 검증

### 능력치 후보

다음 항목은 후보이며 저장 구조가 확인된 항목만 실제로 제공한다.

- 레벨과 경험치
- HP/최대 HP
- 공격·방어·마법 관련 능력치
- 지휘력 또는 부대 관련 능력치
- 이동 및 행동 관련 수치
- 장비·아이템 참조

게임에서 파생 계산되는 값을 직접 수정하면 다음 로드에서 되돌아갈 수 있으므로, 저장 원본 필드와 계산 결과를 구분해 표시한다.

## 5. 종족 변경 안전 규칙

- ROM에서 실제로 사용되는 종족 ID 목록과 이름을 추출한다.
- 존재하지 않는 ID는 입력할 수 없게 한다.
- 캐릭터 record의 종족 ID 외에 그래픽·직업·이동 field가 종속되는지 확인한다.
- 변경 후 편성 화면, 지도 표시와 전투 진입에 필요한 리소스가 존재하는지 검사한다.
- PLAN-015/016의 확장 옵션이 없는 ROM에서도 원본 그래픽 예산을 초과하는 부대가 생길 수 있음을 경고한다.
- 에디터는 부대별 종족 그래픽 비용 합계를 계산해 원본 한도와 확장 한도를 함께 표시한다.

## 6. 저장 정책과 원본 보존

- `memcard/`, `savestates/`, `dos-save/`, `original/`, `patched/`, `korean-patch/`는 수정하지 않는다.
- 에디터는 입력 `.mcd`에 직접 저장하지 않고 기본적으로 새 경로를 요구한다.
- 출력은 임시 파일에 완성한 뒤 재검증하고 원자적으로 배치한다.
- 기존 출력 덮어쓰기는 사용자가 GUI에서 명시적으로 선택한 경우에만 허용한다.
- FQ4가 사용하지 않는 다른 게임 블록은 바이트 단위로 보존한다.
- 변경 허용 범위 밖의 차이가 하나라도 생기면 저장을 중단한다.
- 분석용 복사본은 `work/fq4/save-editor/current-test.mcd` 한 개만 순차 재사용하고 날짜별 복사본을 누적하지 않는다.

GUI와 명령행 도구는 같은 파서·검증 엔진을 사용한다. GUI에서 허용한 값이라도 저장 직전에 엔진에서 다시 범위와 체크섬을 검사한다.

## 8. 검증 절차

### 무변경 왕복

- 기준 메모리카드를 열고 아무것도 바꾸지 않은 출력이 입력과 완전히 동일해야 한다.
- 두 FQ4 슬롯과 다른 블록의 디렉터리·payload가 동일해야 한다.

### 단일 필드 변경

- 한 캐릭터의 능력치 하나만 변경한다.
- 허용된 field와 체크섬 외의 차이가 없는지 검사한다.
- DuckStation에서 로드하고 표시값, 저장 후 재로드와 재저장을 확인한다.

### 종족 변경

- 한 캐릭터의 종족을 다른 유효 종족으로 바꾼다.
- 편성 화면, 지도 sprite, 이동, 전투 진입·종료를 검사한다.
- 변경된 세이브를 다시 저장하고 게임 재시작 후 로드해 유지 여부를 확인한다.
- 원본 한도와 확장 한도에서 부대 종족 예산 경고가 정확한지 확인한다.

### 오류 입력

- 잘린 메모리카드
- 잘못된 `MC` 헤더
- 끊어진 블록 체인
- 잘못된 디렉터리 체크섬
- 알 수 없는 게임 세이브 revision
- 범위를 벗어난 능력치와 종족 ID

각 입력은 원본과 출력 파일을 변경하지 않고 오류로 중단해야 한다.

## 9. 통과 기준

- 두 `BISLPS-00604-*` 슬롯을 안정적으로 검색·추출·재삽입한다.
- 캐릭터 record의 ID, 종족과 제공할 능력치가 게임 코드 또는 런타임 값으로 검증된다.
- 게임 payload와 PS1 디렉터리 체크섬을 정확히 재계산한다.
- 무변경 왕복 결과가 입력과 바이트 단위로 동일하다.
- 능력치와 종족 변경이 DuckStation에서 로드되고 게임 재저장 뒤 유지된다.
- FQ4 이외의 메모리카드 데이터는 바이트 단위로 보존된다.
- 입력 원본은 수정되지 않고 시험용 전체 메모리카드는 한 개만 유지된다.
- GUI와 단일 EXE가 같은 결과를 생성한다.

## 10. 중단 조건

다음 상황에서는 추정값으로 에디터를 배포하지 않고 분석 결과를 보고한 뒤 별도 계획을 작성한다.

- 상태 저장에서 RAM을 재현할 DuckStation 버전을 확보할 수 없음
- 캐릭터 필드가 압축·암호화돼 비교 자료만으로 의미를 확정할 수 없음
- 종족 변경이 여러 런타임 초기화 과정을 요구해 세이브 수정만으로 안전하지 않음
- 게임 내부 체크섬을 확정하지 못함
- 능력치 변경이 저장 구조가 아닌 이벤트 진행 상태와 강하게 결합됨
