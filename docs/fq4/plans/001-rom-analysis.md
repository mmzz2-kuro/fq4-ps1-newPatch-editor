# FQ4-PLAN-001 — 퍼스트퀸4 PS1 ROM 초기 분석 계획

- 작성일: 2026-09-13
- 상태: **초기 분석 완료 — 정적 조사·격리 함수 검증 범위**
- 대상: 사용자 제공 퍼스트퀸4 PS1 원본, 한글패치 적용본, 기존 한글패치
- 완료 문서: `docs/fq4/finish/001-rom-analysis.md`
- 적용 지침: `create-kr-patch` 스킬의 초기 조사, 프로젝트 기록, PS1 지침

## 1. 작업 절차와 승인 범위

사용자 지시에 따라 모든 작업은 다음 순서로 진행한다.

1. `docs/fq4/plans/`에 작업 계획 문서를 작성한다.
2. 사용자가 해당 계획을 확인하고 실행을 승인한다.
3. 승인된 범위의 작업을 실행한다.
4. 작업 종료 시 `docs/fq4/finish/`에 결과, 검증, 미해결 사항을 기록한다.

이 문서 작성은 계획 준비 단계이다. 지금까지 확인한 것은 프로젝트 지침과 폴더·파일명·크기뿐이며, ROM 내부 열람, 해시 계산, 패치 적용, 실행 코드 분석은 승인 후 수행한다. 승인 전에는 분석 스크립트나 분석 결과를 만들지 않는다.

승인 시 이 문서에 승인 일자와 대화에서 확인된 승인 범위를 기록한다. 침묵을 승인으로 간주하지 않는다. 후속 구현, 번역 수정, 새 패치 제작은 별도 계획과 사용자 확인을 거친다. 범위가 실질적으로 확대되면 계획을 갱신하고 추가 확인을 받는다.

### 프로젝트 공통 규칙 — 2026-09-13 사용자 추가 지시

아래 규칙은 이번 분석뿐 아니라 모든 후속 작업과 계획에도 적용한다.

- 원본은 어떤 작업에서도 수정하지 않는다. 제공된 입력은 보존하고 변경은 작업용 파일에만 수행한다.
- 분석·변환 스크립트의 기본 작성 위치는 `tools/scripts/`이다.
- 사용자용 GUI 도구의 작성 위치는 `tools/`이다.
- ROM 복사가 필요할 때 작업용 ROM 한 벌만 마련하여 계속 재사용한다. 작업별·실행별·날짜별 ROM 복사본과 백업을 누적 생성하지 않는다.
- 읽기 전용 분석은 입력을 직접 읽어 불필요한 복사를 피한다. 전체 이미지 출력이 필요한 경우에도 같은 작업용 경로를 재사용한다.
- 작업용 ROM을 재사용하더라도 변환 기준은 보존된 원본으로 고정한다. 재실행 시 필요한 초기화는 같은 작업용 파일을 원본 기준으로 갱신하는 방식으로 수행하고, 의도하지 않은 중복 패치 적용을 방지한다.
- ROM 이력은 전체 이미지 사본 대신 해시, 변경 기록, 스크립트, 재현 명령으로 남긴다.
- 현재 사용자 지시는 규칙 반영만 허용하며, ROM 분석 실행 승인이 아니다.

## 2. 목적

원본과 기존 한글패치의 구조 및 변경 방식을 근거로 파악하여, 별도 한글패치용 BIOS 의존성을 제거하기 위한 구현 경계와 우선순위를 결정한다. 이번 단계에서 게임 전체 해독이나 번역 품질 보증을 목표로 삼지 않는다.

### 문제 배경과 최종 목표 — 2026-09-13 사용자 설명

- 사용자 보고: 기존 한글패치를 적용해도 별도 한글패치용 BIOS인 `korean-patch/SCPH1001.BIN`을 구비하고 설정해야 한다.
- 사용자 불편: 에뮬레이터에서 해당 BIOS를 별도로 준비하고 설정해야 하며, 현재 방식으로는 실기에서 한글 플레이가 되지 않는다.
- 위 내용은 사용자가 제시한 현상이다. BIOS의 실제 변경 내용, 의존 원인 및 실기에서의 실패 경로는 아직 기술적으로 검증하지 않았다.
- **최종 목표: 별도 한글패치용 BIOS 파일을 준비하거나 선택하지 않아도 패치된 디스크 이미지가 필요한 한글 표시 기능을 제공하고, PS1 실기에서도 한글 플레이가 가능하도록 한다.**
- 사용자 제안: `SCPH1001.BIN`을 가급적 패치된 ROM에 포함한다. 이를 우선 검토할 구현 후보로 기록하되, BIOS 파일 전체를 디스크에 넣는 것만으로 게임이 이를 사용한다고 가정하지 않는다.
- 분석에서 BIOS 전체 포함의 필요성, 필요한 글리프·데이터만 디스크로 옮기는 방식, 게임의 폰트 공급·호출 경로를 수정하는 방식을 비교한다. 실제 의존 경로와 실기 제약을 확인한 뒤 근거 있는 구현안을 제시한다.
- 여기서 BIOS 의존성 제거는 **별도 한글패치용 BIOS에 대한 의존 제거**를 뜻한다. PS1 시스템 BIOS 자체가 불필요해진다는 의미가 아니다.
- 실기 목표는 한글 표시와 게임 동작에 관한 것이다. 패치 디스크의 실기 부팅 수단 및 사용 환경은 별도 조건으로 기록하고, 실기 증거 없이 에뮬레이터 성공만으로 실기 지원을 확정하지 않는다.

이 목표의 기록은 ROM 분석 또는 구현의 실행 승인이 아니다. 현재 계획은 계속 사용자 확인 대기 상태로 유지한다.

확인할 핵심 질문:

- 기존 패치는 `SCPH1001.BIN`의 어떤 글리프·데이터·서비스 또는 변경 코드에 의존하며, 어떤 화면과 호출 경로가 영향을 받는가?
- 그 의존성을 디스크 내부 자산과 게임 코드로 대체할 수 있는가? 필요한 RAM·VRAM·디스크 공간, 로딩 시점 및 호출 호환성 조건은 무엇인가?
- 별도 한글 BIOS를 사용하지 않는 에뮬레이터 환경 및 PS1 실기에서 목표를 검증하려면 어떤 대표 화면과 전환 경로를 확인해야 하는가?
- 실제 디스크 형식, 게임 식별자 및 분석 기준 리비전은 무엇인가?
- 제공된 xdelta를 원본에 적용하면 제공된 패치본과 일치하는가?
- 변경된 파일·영역은 무엇이며 텍스트, 폰트, 그래픽 문자, 코드 변경과 어떻게 연결되는가?
- 대표 텍스트의 저장 위치, 인코딩, 제어 코드, 참조 및 표시 경로를 어디까지 확인할 수 있는가?
- 후속 추출·재삽입에 필요한 조건과 아직 검증되지 않은 위험은 무엇인가?

## 4. 실행 계획

### A. 입력 기준 확정

- 입력 파일의 크기와 SHA-256, 상대 경로를 기록한다.
- CUE의 파일 참조, 트랙, 모드, 인덱스를 읽고 BIN과의 일관성을 확인한다.
- 섹터 구조와 파일시스템을 확인하고 부트 설정·실행 파일에서 게임 식별 정보를 조사한다.
- 원본, 패치본, 패치 파일의 역할과 도구 환경을 고정한다. 필요할 때 공식·일차 기술 자료를 확인하고 출처를 기록한다.

산출물: 입력 매니페스트, 디스크 구조 요약, 식별 정보와 미확정 항목.

### B. 기존 패치 재현과 차이 지도

- 동봉 안내 이미지와 패치 메타데이터를 확인한다. 도구 출처·버전을 확인하고 사용한 도구 및 명령을 기록한다.
- 원본을 읽기 전용 입력으로 사용하여 공통 작업용 경로 `work/fq4/rom/current.bin`에 xdelta 적용 결과를 생성한다. 이 파일을 유일한 작업용 ROM으로 재사용하며 별도 원본 복사본이나 실행별 결과 ROM을 추가하지 않는다. 입력 및 기존 패치본을 덮어쓰지 않는다.
- 재현 이미지와 제공된 패치본을 전체 해시 및 필요 시 바이트 비교로 검증한다.
- 불일치 시 입력 리비전, 적용 방법, 도구 조건 등의 후보를 분리하여 기록한다. 임의 보정으로 일치시키지 않는다.
- 원본과 패치본의 연속 변경 구간, 변경 섹터, 논리 파일 차이를 정리한다. 사용자 데이터와 헤더·EDC/ECC 등 부수 변경을 구별한다.

산출물: 패치 재현 판정, 변경 구간 및 파일별 비교표.

### C. 디스크·실행 파일 구조

- 디렉터리, 파일 크기, 파일별 해시, LBA·extent를 목록화한다.
- 이미지 바이트 오프셋, 트랙 섹터, 파일시스템 LBA, 파일 내부 오프셋을 구별하고 검증된 변환식을 기록한다.
- 부트 실행 파일과 텍스트 관련 모듈·오버레이 후보를 조사한다. 실행 파일 로드 정보에 근거하여 파일 위치와 RAM 주소를 연결한다.
- 추출이 필요하면 작업 경로에만 저장한다. 재삽입·재빌드는 이번 단계에서 수행하지 않으며, 후속 재빌드 전에 무변경 왕복 검증이 필요함을 기록한다.

산출물: 파일 목록, 주소 대응표, 현재 확인된 구조.

### D. 텍스트·폰트·한글화 방식 조사

- 최우선 조사 대상은 기존 한글패치의 BIOS 의존 경로이다. 동봉 BIOS의 해시와 구조, 게임 측 BIOS 호출·직접 참조, 문자 코드→글리프 공급 경로를 조사한다. 적법하게 사용 가능한 비교 기준 BIOS가 있을 때만 차이를 대조하고, 비교 기준이 없으면 변경 내용의 확정 한계를 명시한다.
- BIOS 의존성이 폰트 데이터에 국한되는지, 코드·서비스 변경까지 포함하는지 구별한다. 단순 바이너리 차이를 실제 게임의 사용 근거로 취급하지 않는다.
- BIOS 전체 포함, 필요한 자산의 디스크 이관, 게임 측 공급 경로 수정 후보를 공간·메모리·로드 시점·호환성·검증 비용으로 비교한다. BIOS 전체나 내부 자산의 재배포 가능 여부는 출처·권한 확인 전 확정하지 않는다.
- 변경 지도에서 텍스트, 문자 코드표, 글리프·텍스처, 코드 변경 후보를 좁힌다.
- 문자열 검색과 통계는 후보 발굴에 사용한다. 인코딩, 포인터 폭·기준, 종료자, 제어 코드 의미는 실제 참조·소비 코드와 대조한다.
- 대표 텍스트 영역의 원시 바이트와 가역 해석 샘플을 기록한다. 해석 가능한 표본은 재인코딩 바이트 일치 여부를 검증한다.
- 원본과 패치본의 글리프 공급 방식, 코드→글리프 대응, 렌더러 변경 여부를 조사한다. BIOS 폰트 사용 여부는 파일명이나 플랫폼 관례로 추정하지 않는다.
- 대사, 메뉴, 이름, 설명문, 이미지에 그려진 문자 등을 발견 근거와 함께 구분한다. 발견하지 못한 유형은 미확인으로 남긴다.
- 초기 분량은 정확값·하한·추정·미확정으로 표시하고 단위, 중복 처리, 미조사 영역을 명시한다. 검색 문자열 수를 전체 번역량으로 간주하지 않는다.
- 저장된 문장의 길이와 실제 표시 용량을 구별한다. 압축, 버퍼, 글리프 수, 포인터·LBA 고정 참조는 근거가 있을 때 조사한다.

산출물: 텍스트·자산 지도, 대표 표본, 폰트·표시 경로의 확인 사항 및 가설.

### E. 필요한 경우에만 실행 관찰

- 환경이 준비되어 있으면 동일한 패치본과 대표 화면을 기준으로 한글패치용 BIOS 사용/미사용 조건을 비교한다. 사용한 시스템 BIOS의 해시·설정과 화면 차이를 기록하여 의존성을 분리한다. 필요한 BIOS가 없으면 임의로 내려받지 않고 관찰 제약으로 기록한다.
- 정적 조사만으로 대표 저장 데이터와 화면 소비 경로를 연결할 수 없으면, 이용 가능한 에뮬레이터·디버거로 원본과 기존 패치본을 관찰한다.
- 도구 버전, 이미지 해시, 설정, 진입 절차, 화면 및 추적 근거를 기록한다.
- 설치나 환경 제약 때문에 관찰할 수 없다면 정적 근거와 실행 미검증 상태를 구별하고 다음 진단 방법을 제시한다.
- ROM 수정 실험, 신규 코드 훅, 새 폰트 삽입은 별도 PoC 계획으로 분리한다. 이번 승인은 그 구현을 포함하지 않는다.

### F. 결론과 완료 기록

- 한글패치용 BIOS 의존 원인에 대한 확인 수준과 제거 가능성을 우선 결론으로 제시한다. 가장 적합한 구현 후보, 예상 변경 범위, 실기 검증 조건, 결론을 뒤집을 수 있는 미확정 사항을 명시한다.
- 확인된 구조, 기존 패치 방식, 재현 여부, 후속 추출·재삽입의 구현 경계를 정리한다.
- 위험마다 근거, 영향, 다음 판별 실험, 가능한 우회안을 기록한다.
- 필수 PoC와 조건부 PoC를 구별하고, 생략 가능한 검증에는 동등한 기존 근거를 연결한다.
- 완료 문서를 작성하고 다음 작업의 권장 범위를 제시한다. 후속 작업은 자동 착수하지 않는다.

## 5. 보존 및 산출물 경로

- `original/`, `patched/`, `korean-patch/`는 읽기 전용 입력으로 취급한다. 이동·삭제·덮어쓰지 않는다.
- `docs/fq4/analysis/001/`: 입력 매니페스트, 파일·변경 지도, 텍스트 지도, 근거와 위험 목록.
- `tools/scripts/`: 필요할 경우 작성하는 재실행 가능한 분석·변환 스크립트.
- `tools/`: 사용자용 GUI 도구. 이번 계획에는 GUI 개발을 포함하지 않는다.
- `work/fq4/rom/current.bin`: 후속 작업에서도 공통으로 재사용할 유일한 작업용 ROM. CUE가 필요하면 같은 폴더의 `current.cue`를 재사용한다. 승인 후 필요할 때만 생성한다.
- `work/fq4/001/`: 필요한 추출 파일과 분석 근거. 전체 ROM 사본은 저장하지 않으며, 승인 후 필요할 때 생성한다.
- `docs/fq4/finish/001-rom-analysis.md`: 실행 결과와 검증의 최종 기록.
- 원본·파생 디스크 이미지, BIOS, 추출한 대량 게임 자산은 커밋·업로드하지 않는다. 문서에는 해시, 위치, 최소 표본 및 재현 방법을 남긴다.
- 분석 종료 시 입력 해시를 다시 비교하여 내용 보존을 검증한다.
- 작업 종료 시 전체 ROM 복사본이 실행별로 누적되지 않았는지 확인하고, 재사용 중인 작업용 ROM 경로와 현재 해시를 완료 문서에 기록한다.

## 6. 완료 기준

다음을 모두 충족하면 초기 분석 완료로 판정한다.

1. 입력 해시, 식별 정보, 매체 구조와 후속 수정·재빌드 경계가 확인되어 있다.
2. 기존 패치 재현의 일치·불일치 판정과 근거가 있다.
3. 변경 영역이 논리 파일 또는 명확히 표시한 미해석 영역에 연결되어 있다.
4. 대표 텍스트의 가역 해석과 소비 경로가 근거로 연결되어 있다.
5. 텍스트·자산 초기 분량의 확실성 수준 및 미조사 범위가 기록되어 있다.
6. 후속 결정을 바꿀 미해결 위험마다 다음 진단 또는 대안이 있다.
7. 입력 내용 보존이 확인되고 완료 문서가 작성되어 있다.
8. 한글패치용 BIOS 의존 원인과 영향 범위의 확인 수준이 기록되어 있고, 의존성 제거 구현 후보를 비교하여 권장 방향 또는 추가 진단을 제시한다.

필수 근거가 부족하면 위 기준을 충족했다고 표시하지 않는다. 작업 종료 문서에 **부분 완료 또는 차단**, 충족하지 못한 기준, 필요한 후속 작업을 명시한다. 초기 분석 완료는 전체 번역의 정확성, 게임 전체 정상 진행, 배포 준비 완료를 의미하지 않는다.
