# FQ4-PLAN-034 엔딩 후 캐릭터 표시 구간 블랙스크린 조사 및 수정 계획

- 원본 비교 대상: `original/`
- 패치본 비교 대상: `patched/`, `my-patch/`, `korean-patch/`
- 분석 산출물: `docs/fq4/analysis/034/`

## 1. 문제 요약

일본어 원본 버전은 최종 보스 클리어 후 씬 전환 대사가 진행되고, 엔딩 동영상이 재생된 뒤 내 캐릭터들을 다시 보여준 다음 타이틀로 복귀한다.

한글패치 적용 버전은 최종 보스 클리어, 씬 전환 대사, 엔딩 동영상 재생까지는 정상이다. 그러나 엔딩 동영상 이후 내 캐릭터들을 보여주는 구간에서 검은 화면으로 멈추거나 화면이 나오지 않는다.

이 문제는 게임 후반부에서만 확인되는 진행 차단 문제이므로 기존 자금/아이템 세이브 에디터 작업보다 우선순위를 높여 별도 조사한다.

## 2. 목표

- 원본과 한글패치본 사이에서 엔딩 동영상 이후 구간에 영향을 주는 차이를 좁힌다.
- 문제가 파일 누락, 파일 크기/섹터 위치 변경, 포인터 불일치, 실행 코드 패치, 텍스트/폰트 데이터, ECC/EDC, BIOS 의존성 중 어느 범주인지 분리한다.
- 가능한 경우 한글패치 적용 ROM에서 엔딩 후 캐릭터 표시 구간이 정상 진행되도록 수정한다.
- 수정 결과는 원본 ROM이나 기존 패치본을 직접 덮어쓰지 않고, 작업용 출력물로 생성한다.

## 3. 우선 가설

1. **섹터/파일 배치 문제**
   - 엔딩 동영상 이후 로드하는 파일이 패치 과정에서 위치나 크기가 바뀌었고, 실행 파일 내부 테이블 또는 파일 인덱스가 맞지 않을 수 있다.

2. **엔딩 후 캐릭터 표시용 데이터 손상 또는 포인터 오류**
   - 게임 내 캐릭터 표시 구간에서 필요한 이름, 클래스, 스프라이트, 상태 데이터 접근이 한글패치 변경과 충돌했을 수 있다.

3. **BIOS 글리프/한글 폰트 주입 영향**
   - 기존 한글패치가 BIOS 의존 방식으로 후반부 특수 표시 루틴을 처리하면서, 엔딩 이후 표시 루틴에서 필요한 글리프나 VRAM 배치가 깨질 수 있다.

4. **ECC/EDC 또는 CD 이미지 보정 문제**
   - 이전에 cue/bin의 ECC/EDC 배드섹터 이슈가 있었으므로, 엔딩 이후 특정 섹터 접근에서 오류가 드러날 수 있다.

5. **기존 xdelta 버전 차이**
   - 현재 `patched/`가 `(241112).xdelta` 적용본으로 확인된 적이 있으므로, 다른 한글패치 버전과의 차이가 문제 원인일 수 있다.

## 4. 분석 절차

### 4.1 현재 보유 파일 정리

- `original/`, `patched/`, `my-patch/`, `korean-patch/`의 cue/bin, 실행 파일, 패치 파일 목록을 해시와 크기로 기록한다.
- 원본과 패치본의 트랙 크기, 섹터 수, Mode2/2352 정합성을 확인한다.
- 기존 ECC/EDC 보정 스크립트와 산출물이 있다면 어떤 이미지가 정상 보정본인지 확인한다.

### 4.2 원본/패치본 구조 비교

- PS1 실행 파일과 주요 데이터 파일의 위치, 크기, 파일 테이블 후보를 비교한다.
- 이미 확인된 `FS2_FILE.DAT`, `SLPS_...` 구조를 재사용한다.
- 엔딩 동영상 파일과 그 직후 로드될 가능성이 있는 파일/섹터 주변을 비교한다.

### 4.3 엔딩 경로 재현 자료 수집

- 사용자가 보유한 최종 보스 직전 세이브, 엔딩 동영상 직후 savestate, 블랙스크린 savestate가 있으면 분석 대상으로 삼는다.
- 새 파일 요청은 필요한 시점에만 한다. 우선 현재 `memcard/`와 `savestates/`에 있는 자료부터 확인한다.

### 4.4 런타임 단서 추출

- DuckStation savestate가 있다면 현재 PC, 로드 주소, CD 접근 위치, RAM 내 문자열/파일명/상태 값을 추출할 수 있는지 확인한다.
- 원본 정상 진행 상태와 패치본 블랙스크린 상태를 비교할 수 있으면 멈춘 루틴을 좁힌다.

### 4.5 수정 후보 작성

원인에 따라 다음 중 하나로 수정한다.

- 파일 테이블/섹터 포인터 보정
- 엔딩 후 표시 구간에서 참조하는 데이터 복구
- BIOS 의존 글리프/폰트 참조 제거 또는 내장 폰트 경로로 전환
- ECC/EDC 재생성 및 cue/bin 정합화
- 특정 xdelta 버전 차이에 따른 패치 재생성

## 5. 검증

- 원본과 패치본의 차이를 문서화한다.
- 수정본은 `work/` 또는 `out/`에만 생성한다.
- 엔딩 동영상 이후 캐릭터 표시 구간까지 진행되는지 확인한다.
- 가능하면 타이틀 복귀까지 확인한다.
- 최소한 정적 검증으로 수정 범위, 섹터 정합성, ECC/EDC 상태를 기록한다.

## 6. 원본 보존

`original/`, `patched/`, `korean-patch/`, `memcard/`, `savestates/`, `dos-save/`의 원본 파일은 직접 수정하지 않는다. 분석은 읽기 전용으로 수행하고, 수정 실험은 `work/` 또는 `out/` 아래의 작업용 파일로 제한한다.

## 7. 완료 조건

- 엔딩 후 블랙스크린 원인 후보가 근거와 함께 좁혀진다.
- 수정 가능성이 높은 경로가 하나 이상 제시된다.
- 가능한 경우 수정본 또는 패치 생성 절차가 만들어진다.
- 확인된 결과와 남은 리스크를 `docs/fq4/finish/034-ending-post-movie-black-screen.md`에 기록한다.
