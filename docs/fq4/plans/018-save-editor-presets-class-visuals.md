- 사용자용 도구: `tools/FQ4SaveEditor/`

- 완료 문서 예정: `docs/fq4/finish/018-save-editor-presets-class-visuals.md`

## 1. 목적

캐릭터마다 같은 능력치를 반복 입력하는 불편을 줄이기 위해 사용자가 능력치 프리셋을 만들고 선택한 캐릭터에 한 번에 적용하는 기능을 추가한다. CLASS 선택 화면에는 이름과 함께 실제 게임 그래픽을 표시해 일본어·영어 이름만으로 구분하기 어려운 문제를 해결한다.

## 2. 확정 수치 제한

GUI와 저장 엔진 양쪽에서 다음 범위를 강제한다.

| 항목 | 최소 | 최대 |
|---|---:|---:|
| HR | 1 | 16 |
| HP | 1 | 999 |
| AT | 1 | 99 |
| AR | 1 | 99 |
| DF | 1 | 99 |
| DR | 1 | 99 |

LV와 FT는 현재 게임 데이터에 0이 존재하므로 이번에 임의의 최소·최대 제한을 추가하지 않고 기존 범위를 유지한다. 프리셋은 위 여섯 항목을 기본 대상으로 하며, CLASS·LV·FT는 각 프리셋에서 선택적으로 포함할 수 있게 한다. 포함하지 않은 항목은 캐릭터의 현재 값을 보존한다.

잘못된 값은 입력 단계와 최종 저장 단계에서 모두 거부한다. 기존 메모리카드에 범위를 벗어난 값이 있으면 파일을 여는 것은 허용하되, 해당 값을 수정·저장하려 할 때 명확한 오류를 표시한다.

## 3. 프리셋 기능

### 프리셋 데이터

사용자가 다음 항목으로 프리셋을 만들 수 있게 한다.

- 프리셋 이름
- HR, HP, AT, AR, DF, DR
- 선택 항목: LV, FT
- 선택 항목: CLASS

프리셋은 ROM이나 메모리카드에 넣지 않고 에디터 설정 파일로 보관한다. 개발 소스에서는 기본 프리셋 JSON 스키마와 검증 코드를 `tools/FQ4SaveEditor/`에 둔다. 배포 EXE에서는 사용자별 쓰기 가능한 설정 위치에 저장해 EXE를 교체해도 프리셋이 유지되게 한다.

### GUI 동작

- 프리셋 목록 선택
- 새 프리셋 생성
- 현재 입력값으로 프리셋 저장
- 기존 프리셋 이름 변경 및 삭제
- 선택 캐릭터 한 명에 적용
- 목록에서 여러 캐릭터를 선택해 일괄 적용
- 실제 파일에 쓰기 전 변경될 인원과 항목을 요약 표시
- 적용 후에도 `.mcd` 저장 전까지는 메모리에서만 변경

프리셋 삭제는 사용자가 GUI에서 명시적으로 선택하고 확인한 경우에만 수행한다. 기본 제공 프리셋이 필요하면 사용자 프리셋과 구분해 원복할 수 있게 한다.

## 4. CLASS 이미지 카탈로그

### 분석 목표

현재 확인된 150개 CLASS ID를 게임의 실제 캐릭터 그래픽과 연결한다. CLASS 이름표와 그래픽 비용표만으로 이미지를 추정하지 않고 다음 경로를 실행 코드와 데이터로 추적한다.

1. CLASS ID가 스프라이트 또는 애니메이션 ID로 변환되는 표를 찾는다.
2. 해당 그래픽이 PS1 BIN의 어느 파일·블록에서 로드되는지 확인한다.
3. 압축·팔레트·타일 배치를 분석해 대표 정지 프레임을 재구성한다.
4. 게임 화면 또는 DuckStation RAM/VRAM 캡처와 비교한다.
5. CLASS ID별 대표 이미지, 출처 오프셋과 검증 상태를 카탈로그로 기록한다.

### UI 표시

일반 콤보박스는 이미지 표시가 제한되므로 CLASS 선택 전용 창을 추가한다.

- 이미지 타일 또는 이미지가 포함된 목록
- CLASS ID와 정리된 표시명
- 현재 선택된 CLASS 강조
- 이름과 ID 검색
- 이미지가 확인되지 않은 CLASS는 임시 아이콘과 `미확인` 표시
- 선택 결과를 캐릭터 편집 화면에 반영

기본 편집 화면에도 현재 CLASS의 확대 아이콘과 ID·이름을 함께 표시한다. 사용자가 제시한 예시처럼 그림을 보고 CLASS를 고를 수 있는 구성을 목표로 한다.

## 5. 이름 정리 원칙

일본어와 영어가 섞인 현재 표시명을 CLASS ID 기준의 단일 카탈로그로 정리한다.

- 게임 데이터의 원문 이름
- 가능한 경우 영문 이름
- 이해하기 쉬운 한글 표시명
- CLASS ID
- 대표 이미지

번역이 불확실한 이름은 추측으로 확정하지 않고 원문과 ID를 함께 표시한다. 중복 이름은 이미지와 ID로 구분한다.

## 6. 원본 보존과 파일 배치

- `original/`, `patched/`, `korean-patch/`, `memcard/`, `savestates/`, `dos-save/`는 수정하지 않는다.
- 분석·추출·변환 스크립트는 `tools/scripts/`에 작성한다.
- 사용자 GUI 소스와 작은 이미지 리소스는 `tools/FQ4SaveEditor/`에 둔다.
- 분석용 대용량 ROM 복사본은 새로 만들지 않고 기존 작업본을 재사용한다.
- CLASS 이미지 중간 결과는 `work/fq4/018/` 한 위치에서 갱신하며 날짜별 복사본을 누적하지 않는다.
- 최종 GUI에는 필요한 대표 이미지와 카탈로그만 포함한다.
- 입력 메모리카드는 직접 수정하지 않고 항상 새 경로로 저장하는 기존 정책을 유지한다.

## 8. 검증 절차

### 수치 제한

- 각 항목의 최소값과 최대값 저장 성공
- 각 항목의 최소 미만과 최대 초과 입력 거부
- GUI 검증을 우회해도 저장 엔진에서 거부
- LV·FT와 편집하지 않은 레코드 보존

### 프리셋

- 생성·저장·재시작 후 복원
- 선택 항목만 적용되고 제외 항목은 보존
- 한 명 및 다중 선택 일괄 적용
- 삭제 확인과 손상된 프리셋 파일 복구
- 프리셋 적용 후 체크섬과 변경 범위 검증

### CLASS 이미지

- 150개 CLASS ID의 카탈로그 entry 존재
- 이미지가 확정된 모든 entry의 출처와 SHA-256 기록
- 서로 다른 ID가 같은 그래픽을 쓰는 경우 중복 관계 기록
- 대표 CLASS를 DuckStation 화면과 시각 비교
- 미확인 이미지를 다른 CLASS 이미지로 임의 대체하지 않음

### 회귀 검증

- PLAN-017의 두 슬롯 탐지와 12개 화면 대조 유지
- 무변경 왕복 완전 일치
- 단일·다중 캐릭터 수정에서 허용 범위 외 차이 없음
- 다른 메모리카드 블록과 PS1 디렉터리 보존
- 단일 EXE 실행 및 프리셋 저장 위치 확인

## 10. 완료 기준

- 사용자가 반복 입력 없이 저장한 프리셋을 한 명 또는 여러 캐릭터에 적용할 수 있다.
- HR·HP·AT·AR·DF·DR이 지정 범위 밖으로 저장되지 않는다.
- 150개 CLASS가 빠짐없이 선택 목록에 존재한다.
- 확인된 CLASS는 실제 게임 대표 이미지와 함께 표시된다.
- 이미지 미확인 항목은 명확히 구분되고 잘못된 그림으로 대체되지 않는다.
- 원본 자료와 입력 메모리카드가 수정되지 않는다.
- 갱신된 단일 EXE와 PLAN-018 완료 문서가 생성된다.
