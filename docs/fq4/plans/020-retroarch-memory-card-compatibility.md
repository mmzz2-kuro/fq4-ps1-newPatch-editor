# FQ4-PLAN-020 RetroArch 메모리카드 호환성 분석

- 작성일: 2026-09-14
- 상태: **완료**
- 대상 파일: `memcard/retroarch/fq4-kor-250826.srm`
- 연계 도구: `tools/FQ4SaveEditor/`
- 완료 문서 예정: `docs/fq4/finish/020-retroarch-memory-card-compatibility.md`

## 1. 목적

RetroArch에서 생성한 131,072바이트 `.srm` 파일을 현재 FQ4 PS1 세이브 에디터가 `.mcd`와 동일하게 안전하게 읽고 편집·저장할 수 있는지 확인한다. 크기가 같다는 사실만으로 호환된다고 단정하지 않고 PS1 메모리카드 구조와 게임 데이터까지 비교한다.

## 2. 분석 항목

- `.srm` 파일의 크기, 선두 시그니처, 디렉터리 프레임 및 블록 구조 확인
- 기존 `memcard/`의 FQ4 `.mcd` 표본과 컨테이너 구조 비교
- FQ4 저장 슬롯 식별자와 4블록 연결 구조 탐지 여부 확인
- 저장 데이터 내부 체크섬 8개 검증
- 현재 `fq4_memcard.py`로 읽기 및 무변경 왕복 저장이 가능한지 확인
- 무변경 왕복 결과가 입력 바이트와 완전히 같은지 확인
- `.srm` 확장자를 GUI 파일 열기·다른 이름으로 저장 화면에서 지원해야 하는지 판단

## 3. 구현 판단

분석 결과에 따라 다음 중 하나로 처리한다.

1. **원시 128KiB PS1 메모리카드와 완전히 동일**: 엔진은 유지하고 GUI 파일 필터와 안내 문구에 `.srm`을 추가한다.
2. **구조는 호환되지만 일부 메타데이터 차이가 있음**: 차이를 보존하도록 입출력 로직을 보완한다.
3. **별도 RetroArch 컨테이너 또는 코어 종속 형식**: 자동 판별·변환 가능 범위를 문서화하고 안전한 경우에만 지원한다.

출력 확장자는 기본적으로 입력 확장자를 유지하며, 원본 파일을 덮어쓰지 않는 `다른 이름으로 저장` 방식을 유지한다.

## 4. 검증

- 원본 `.srm`을 읽기 전과 분석 후 SHA-256으로 비교해 원본 보존을 확인한다.
- 제어된 작업 파일은 `work/fq4/save-editor/` 아래 하나만 사용하고 반복 복사하지 않는다.
- 무변경 왕복 바이트 일치 검사와 제한된 캐릭터 필드 변경 검사를 수행한다.
- 변경 범위, 디렉터리 체인 및 게임 체크섬을 다시 검증한다.
- 지원 코드를 수정한 경우 기존 `.mcd` 회귀 테스트도 함께 실행한다.
- 최종 지원 결과를 완료 문서에 기록한다.

## 5. 원본 보존

`memcard/retroarch/`와 기존 `memcard/`의 파일은 읽기만 하며 수정하지 않는다. `original/`, `patched/`, `korean-patch/`, `savestates/`, `dos-save/`도 수정하지 않고 ROM 복사본을 만들지 않는다.

## 6. 완료 조건

- 제공된 RetroArch `.srm`의 실제 형식과 FQ4 슬롯 상태가 확인된다.
- 현재 에디터에서의 호환 여부와 필요한 수정 범위가 명확해진다.
- 호환 가능한 경우 `.srm` 열기·편집·확장자 유지 저장을 지원하고 검증한다.
- `docs/fq4/finish/020-retroarch-memory-card-compatibility.md`를 작성한다.
