# FQ4-PLAN-005 — 전체 사용 글리프 조사 및 제품용 폰트 구조 설계 계획

- 작성일: 2026-09-13
- 상태: **사용자 확인 대기**
- 선행 결과: [FQ4-FINISH-004](../finish/004-menu-glyph-poc.md)

- 작업 ROM: `work/fq4/rom/current.bin` 한 벌
- 완료 문서 예정: `docs/fq4/finish/005-full-font-architecture.md`

## 1. 목적

250826 한글패치가 실제로 사용하는 한글 코드와 글리프를 전부 열거한다. 동봉 한글 BIOS의 전체 글리프 영역과 대조해 필요한 글리프 수와 용량을 확정하고, PS1 디스크에 저장한 폰트를 RAM으로 적재하여 기존 렌더러가 조회할 수 있는 제품용 구조를 설계한다.

이번 단계의 핵심은 “BIOS 글리프를 모두 복사하면 되는가”를 수치와 실행 경로로 판단하는 것이다. 실제 사용 글리프만 넣는 방식과 전체 한글 BIOS 글리프 영역을 넣는 방식을 용량, 조회 비용, RAM, 로딩 시점과 배포 경계 측면에서 비교한다.

## 2. 승인 범위

- 250826 패치본의 모든 ISO 파일과 실행 파일에서 한글 코드 후보를 조사한다.
- 문자열 경계, 제어 코드, 포인터와 렌더러 호출을 이용해 텍스트와 바이너리 오탐을 분리한다.
- 실제 사용 문자, 사용 코드, 출현 횟수, 파일·오프셋과 호출 경로를 기록한다.
- 동봉 한글 BIOS에서 유효한 한글 글리프 전체 범위와 사용 글리프 부분집합을 식별한다.
- 사용 글리프만 저장하는 안과 전체 글리프를 저장하는 안의 디스크·RAM 용량을 계산한다.
- 게임의 파일 테이블, CD 읽기 함수, 초기화 순서, RAM 맵과 화면 전환 경로를 조사한다.
- 폰트 저장 위치, 로드 시점, RAM 주소, 조회 알고리즘과 BIOS 폴백 정책을 설계한다.
- 선택 구조의 최소 로더·조회 코드를 격리 환경에서 조립하고 ABI와 load delay를 검증한다.
- 결과와 다음 구현 계획에 필요한 정확한 입력을 완료 문서에 기록한다.

이번 승인에서는 전체 글리프를 `current.bin`에 삽입하거나 제품용 로더를 적용하지 않는다. ROM 변경은 설계가 검증된 뒤 별도 계획과 사용자 확인을 거친다.

## 3. 보존 및 용량 규칙

- `original/`, `patched/`, `korean-patch/`는 읽기 전용이며 수정·이동·삭제하지 않는다.
- 분석은 현재 파일을 직접 읽어 수행하고 전체 ROM 복사본을 추가 생성하지 않는다.
- `work/fq4/rom/current.bin`은 PLAN-004 메뉴 PoC 상태 그대로 유지한다.
- 대용량 중간 추출물 대신 코드 목록, 범위, 해시와 통계만 보존한다.
- 글리프 미리보기가 필요하면 중복 제거된 작은 이미지나 글리프 바이너리만 `work/fq4/005/`에 둔다.
- 분석·변환·검증 스크립트는 `tools/scripts/`에 작성한다.
- 사용자용 GUI는 만들지 않는다.
- 동봉 BIOS에서 추출한 글리프는 로컬 연구 입력으로만 취급하며 이번 단계에서 배포 파일을 만들지 않는다.

## 5. 조사 절차

### A. 한글 인코딩 범위 확정

1. KS X 1001 행·열을 Shift-JIS 위치로 옮기는 현재 매핑을 전체 유효 범위에 적용한다.
2. 동봉 한글 BIOS의 글리프 기준 주소 `0x5F82C`, 30바이트 stride와 마지막 유효 글리프 경계를 재검증한다.
3. 일반 BIOS와 동봉 BIOS의 차이 범위 `0x69D68..0x7B0CB`를 글리프 인덱스에 맞춰 해석한다.
4. 한글, 공백, 구두점, 일본어 폴백과 미사용 슬롯을 구분한다.

### B. 패치본 전체 텍스트 후보 추출

1. 250826 패치본의 Form 1 파일을 모두 순회한다.
2. 유효 한글 코드가 연속되는 구간을 후보 문자열로 추출한다.
3. 문자열 전후의 종단, 제어 코드, 포인터 정렬과 레코드 구조를 기록한다.
4. 원본·250826 파일 차이와 대조하여 패치가 추가하거나 변경한 구간을 우선한다.
5. XA, 압축 데이터, 그래픽과 기계어에 우연히 나타난 바이트를 별도로 분류한다.

### C. 사용 글리프 집합 확정

후보 코드는 다음 근거 중 둘 이상이 일치해야 사용 글리프로 확정한다.

- 패치 변경 구간 안에 존재한다.
- 유효한 문자열 경계나 레코드 구조 안에 존재한다.
- 문자열 포인터 또는 렌더러 호출 경로가 확인된다.
- 동봉 BIOS에서 비어 있지 않은 예상 글리프를 반환한다.
- 실제 게임 런타임의 글리프 조회에서 관찰된다.

각 확정 글리프에 문자, 게임 코드, EUC-KR/JIS 행·열, BIOS 오프셋, 30바이트 해시, 출현 파일과 횟수를 연결한다. 확정·후보·제외 집합을 분리해 오탐률과 미검출 위험을 기록한다.

### D. 용량 비교

다음 두 안을 비교한다.

| 안 | 저장 데이터 | 장점 | 검토할 비용 |
|---|---|---|---|
| 사용 글리프 집합 | 실제 확인된 글리프만 압축 없이 저장 | 디스크·RAM 사용량이 작음 | 코드→인덱스 테이블 필요, 누락 위험 |
| 전체 한글 글리프 영역 | 동봉 BIOS의 유효 한글 슬롯 전체 | 조회 계산이 단순하고 누락 위험이 낮음 | 약 70KB 이상 저장·RAM 필요 가능성 |

각 안에 대해 글리프 데이터, 인덱스 또는 비트셋, 정렬, 섹터 패딩, 로더 코드와 RAM 상주량을 계산한다.

### E. 디스크 저장 후보 조사

- 기존 ISO 파일의 빈 영역, 미사용 파일, 확장 가능한 파일과 게임 고유 컨테이너를 조사한다.
- 파일 크기를 늘릴 경우 뒤 extent와 게임 내부 LBA 테이블에 미치는 영향을 계산한다.
- 새 파일 추가와 기존 파일 확장의 호환성, CUE·Mode 2 Form, EDC/ECC 갱신 범위를 비교한다.
- 오디오·XA 스트림, 디렉터리 레코드와 정렬 경계를 침범하지 않는 후보만 남긴다.
- 최종 후보마다 raw LBA, 논리 파일 오프셋, 최대 용량과 필요한 메타데이터 변경을 기록한다.

### F. RAM과 로더 경로 조사

- PS-X EXE 적재 범위, BSS, 힙, 스택, 오버레이, 전투·지도 버퍼와 CD 버퍼를 정리한다.
- 한 시점의 0 값만으로 빈 RAM을 확정하지 않는다. 초기화 코드와 화면 전환 시 읽기·쓰기를 함께 확인한다.
- 부팅 시 1회 적재, 메뉴 진입 시 적재, 주문형 페이지 적재를 비교한다.
- CD 읽기 함수의 모드, 섹터 단위, DMA/IRQ, 캐시 무효화와 실패 처리를 조사한다.
- 세이브 로드, 전투↔지도 전환과 재초기화 뒤에도 폰트가 유효한지 설계에 포함한다.

### G. 조회 구조와 BIOS 폴백 설계

- 사용 글리프 안은 정렬된 코드 테이블, 직접 인덱스 또는 2단계 행 테이블을 비교한다.
- 전체 글리프 안은 코드에서 KS X 1001 인덱스를 계산해 RAM 글리프 주소로 변환하는 방식을 검토한다.
- 일본어·숫자·기호와 범위 밖 코드는 기존 BIOS `B0(51h)`로 전달한다.
- ABI, 저장 레지스터, branch/load delay, 주소 캐시와 실패 반환을 명세한다.
- 조회 최악 시간과 한 화면 최대 글리프 업로드 비용을 계산한다.

### H. 격리 설계 검증

- 선택한 주소 계산 또는 테이블 조회 코드를 MIPS R3000A용으로 조립한다.
- 모든 load delay와 branch delay를 명시적으로 감사한다.
- 경계 코드, 첫·마지막 글리프, 미등록 코드와 BIOS 폴백을 격리 실행한다.
- 대표 글리프의 30→128바이트 변환 결과가 기존 기준과 일치하는지 확인한다.
- 실제 ROM에는 쓰지 않고 코드 크기, 데이터 크기와 예상 패치 범위만 산출한다.

## 6. 설계 판정 기준

### 통과

1. 확정 사용 글리프와 미확정 후보가 분리되어 있다.
2. 각 확정 글리프가 코드·문자·BIOS 위치·해시와 출현 근거를 가진다.
3. 사용 글리프 안과 전체 글리프 안의 정확한 디스크·RAM 비용이 계산된다.
4. 디스크 저장 위치와 RAM 상주 위치에 정적 구조 및 런타임 수명 근거가 있다.
5. 로드 시점, CD 읽기 경로와 재초기화 정책이 명시된다.
6. 조회·폴백 코드의 ABI와 R3000A 지연 슬롯이 검증된다.
7. 다음 구현 계획에 필요한 주소, 크기, 입력 해시와 예상 변경 범위가 확정된다.
8. 원본과 현재 작업 ROM이 보존되고 전체 ROM은 한 벌만 유지된다.

### 부분 통과 또는 미해결

- 텍스트 형식이나 압축 때문에 전체 사용 코드 집합을 확정하지 못한다.
- 장시간 런타임 추적 없이 안전한 RAM 수명을 입증할 수 없다.
- 파일 확장에 필요한 게임 내부 LBA 테이블의 소비 경로가 불명확하다.
- 사용 글리프 안과 전체 글리프 안 중 하나를 선택할 근거가 부족하다.

이 경우 확정 범위와 첫 미확인 경계를 구분하고, 근거 없이 ROM 구현으로 넘어가지 않는다.

### 실패

- 입력 계보나 해시가 기준과 다르다.
- 후보 저장 위치가 ISO·XA 또는 게임 데이터와 충돌한다.
- 안전한 RAM 상주 범위나 재적재 경로를 찾지 못한다.
- 조회 구조가 기존 렌더러 ABI 또는 성능 한계를 충족하지 못한다.
