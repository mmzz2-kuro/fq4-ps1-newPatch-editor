# FQ4-PLAN-006 — 전체 한글 글꼴 런타임 구현 계획

- 작성일: 2026-09-13
- 상태: **사용자 확인 대기**
- 선행 결과: [FQ4-FINISH-005](../finish/005-full-font-architecture.md)

- 완료 문서 예정: `docs/fq4/finish/006-full-font-runtime-implementation.md`

## 1. 목적

250826 한글 패치가 사용하는 KS X 1001 완성형 한글 2,350자의 30바이트 글리프를 게임 디스크에 저장하고, 일반 PS1 BIOS에서도 게임이 이를 RAM으로 읽어 기존 문자 렌더러에 공급하도록 구현한다. 성공하면 별도의 한글 BIOS 없이 에뮬레이터와 실기에서 한글을 표시할 수 있는 제품 구조의 기반이 된다.

PLAN-005에서 선택한 `DUMMY.DUM` 저장안과 게임 메모리 풀 상단 예약안을 실제 코드에 적용한다. 먼저 두 구조의 안전 근거를 실행·정적 분석으로 확인하며, 안전 관문을 통과하지 못하면 ROM에 쓰지 않고 대안을 기록한다.

## 2. 승인 범위

- `DUMMY.DUM`의 런타임 접근 여부와 내부 LBA 참조를 조사한다.
- 게임의 CD 초기화, 섹터 읽기, 완료 대기와 오류 처리 함수를 식별한다.
- 전체 글꼴 payload와 식별 헤더를 재현 가능하게 생성한다.
- 주 메모리 풀 상단을 70,656바이트 줄이고 해당 주소를 글꼴 영역으로 예약한다.
- 부팅 중 글꼴을 35개 섹터에서 RAM으로 한 번 읽는 로더를 구현한다.
- PLAN-004 조회 훅을 2,350자 산술 조회와 BIOS fallback 구조로 교체한다.
- 기존 `current.bin` 한 벌에만 디스크 데이터와 실행 파일 변경을 적용한다.
- Mode 2 Form 1 EDC/ECC, ISO 구조, MIPS ABI와 런타임 표시를 검증한다.
- 결과와 남은 위험을 완료 문서에 기록한다.

배포용 xdelta, 사용자 GUI, 한글 BIOS 파일 배포와 번역문 수정은 이번 범위에 포함하지 않는다.

## 3. 보존 및 용량 규칙

- `original/`, `patched/`, `korean-patch/`는 읽기 전용으로 취급하며 수정·이동·삭제하지 않는다.
- BIOS는 글리프를 추출하는 로컬 입력으로만 사용한다. BIOS 전체 또는 BIOS 코드·데이터를 패치 산출물에 포함하지 않는다.
- 전체 작업 ROM은 `work/fq4/rom/current.bin` 한 벌만 유지한다. 새 BIN·ISO·IMG 복사본을 만들지 않는다.
- 빌더는 변경 전 모든 고정 해시와 바이트를 검사하고, 변경안을 메모리에서 완성·검증한 뒤 `current.bin`을 한 번에 교체한다.
- 실패 시 부분 적용 파일을 남기지 않는다. 쓰기 전 실패하거나 기존 PLAN-004 상태를 복원한다.
- 분석·추출·빌드·검증 스크립트는 `tools/scripts/`에 작성한다.
- 로그와 작은 추출물만 `work/fq4/006/`에 보관한다. 70,500바이트 글꼴 payload는 필요할 때 재생성하며 전체 ROM 중간본은 남기지 않는다.

## 5. 실행 절차

### A. `DUMMY.DUM` 안전 관문

1. ISO 디렉터리 레코드, extent, 크기와 35개 대상 섹터의 Form·서브헤더를 다시 확인한다.
2. 실행 파일과 게임 데이터에서 `DUMMY.DUM`의 LBA, 크기, 시작·끝 sector 값을 little/big endian 및 테이블 문맥으로 검색한다.
3. CD 읽기 함수에 런타임 breakpoint 또는 추적을 걸어 부팅, 타이틀, 새 게임, 지도 메뉴 진입까지 읽힌 LBA 범위를 기록한다.
4. 대상 LBA `24184..24218` 접근이 기존 게임 동작에서 관찰되면 용도를 밝히기 전 쓰지 않는다.
5. 파일이 seek timing 또는 물리 배치용인지 검토한다. extent와 전체 디스크 크기는 어떤 경우에도 유지한다.

정적 미참조와 런타임 미접근이 함께 확인되어야 저장 위치를 승인한다. 확인되지 않으면 빈 영역·별도 컨테이너 등 대체 저장안을 새 계획으로 분리한다.

### B. CD 읽기 경로와 주입 시점 확정

1. CD-ROM 하드웨어 레지스터 접근, PsyQ/BIOS wrapper와 호출 그래프를 찾아 읽기 API를 식별한다.
2. sector 주소 형식이 raw LBA, MSF 또는 파일 상대 offset인지 확인한다.
3. 읽기 단위, 목적지 정렬, 캐시 처리, DMA 완료 대기, 반환값과 오류 재시도 규칙을 기록한다.
4. CD 초기화가 끝났고 게임 주 메모리 풀이 확정된 뒤이며 한글 렌더링 이전인 호출 지점을 선택한다.
5. 기존 로더를 재사용할 수 없으면 최소 직접 로더를 설계하되 인터럽트·DMA 상태를 기존 게임과 공유하는 방식을 피한다.

### C. 전체 글꼴 payload 생성

1. 동봉 한글 BIOS의 `0x69D60`부터 70,500바이트를 2,350개 글리프로 추출한다.
2. 헤더에 magic, 형식 버전, 글리프 수, stride, 데이터 크기와 해시 또는 CRC를 기록한다.
3. 35개 sector payload에 헤더와 글리프를 넣고 남은 부분은 결정적인 값으로 채운다.
4. 첫 글자, 마지막 글자와 PLAN-004에서 확인한 13개 글리프가 기존 BIOS 기준과 바이트 단위로 일치하는지 검사한다.
5. payload 생성 결과와 모든 입력 해시를 manifest에 기록한다.

### D. RAM 예약과 로더 구현

1. malloc 성공 뒤 자체 풀 초기화 직전의 size를 70,656바이트 줄인다.
2. `font_base = pool_pointer + reduced_pool_size`로 계산하고 전역 포인터·상태를 안전한 실행 파일 데이터 영역에 둔다.
3. 남은 pool 크기가 정렬·최소 크기 조건을 만족하는지 실행 중 확인한다.
4. 35개 섹터를 `font_base`로 읽고 완료와 헤더를 검증한 뒤 `font_ready=1`을 설정한다.
5. 읽기·검증 실패 시 `font_ready=0`을 유지하고 기존 BIOS 글리프 경로로 진행하여 부팅 실패를 막는다.
6. 재초기화, 게임 리셋과 세이브 로드 뒤 포인터 수명이 유지되는지 확인한다.

### E. 전체 글리프 조회 훅 구현

1. PLAN-004 임시 13자 테이블과 글리프 데이터를 제거하고 범용 산술 조회 코드로 교체한다.
2. Shift-JIS를 JIS 행·셀로 역변환하고 행 `0x30..0x48`, 셀 `0x21..0x7E`만 내장 글꼴로 처리한다.
3. 주소는 `font_base + ((row-0x30)*94 + (cell-0x21))*30`으로 계산한다.
4. `font_ready=0`, 잘못된 코드 또는 비한글 코드는 입력 `a0`를 보존해 BIOS `B0(51h)`로 전달한다.
5. R3000A load delay, branch/jump delay slot, 호출자 저장 레지스터와 반환 ABI를 명시적으로 검사한다.

### F. 원자적 ROM 빌드

1. 안전 관문과 모든 정적·격리 검사가 통과한 뒤에만 빌드를 허용한다.
2. 빌더는 현재 `current.bin`을 읽어 RAM에서 새 이미지를 만들고 예상 변경 범위를 검증한다.
3. `DUMMY.DUM`의 지정 payload와 `SLPS_006.04`의 승인된 코드·데이터 범위만 변경한다.
4. 수정된 각 Mode 2 Form 1 sector의 EDC와 P/Q ECC를 재계산한다.
5. 임시 파일은 같은 파일시스템에서 사용하고 검증 완료 후 `current.bin`을 원자적으로 교체한다.
6. CUE, 전체 크기, ISO 디렉터리, extent와 변경 sector 목록을 다시 검사한다.

### G. 정적·격리 검증

- 2,350개 모든 코드의 반환 주소와 첫·마지막 경계를 검사한다.
- 일반 일본어·ASCII·제어 코드와 준비 전 상태가 BIOS fallback으로 전달되는지 확인한다.
- 추출 글리프와 RAM 적재 후 데이터의 해시를 비교한다.
- 로더 실패, 잘못된 헤더와 CD 오류 경로를 격리 실행한다.
- 훅과 로더를 역어셈블하여 모든 지연 슬롯과 메모리 범위를 확인한다.
- ROM diff가 manifest에 기록한 sector와 바이트 범위를 벗어나지 않는지 검사한다.

### H. 일반 BIOS 런타임 검증

1. 일반 BIOS로 cold boot하고 글꼴 35개 sector 읽기, 목적지 주소, 완료 상태를 기록한다.
2. 타이틀부터 지도 메뉴까지 비한글 UI와 한글 UI가 유지되는지 확인한다.
3. 최소 확인 문자열은 `교섭중`, `시간경과`, `부대이동`, `탐색`으로 한다.
4. 전투 진입·종료, 부대 이동, 지역 이동, 메뉴 반복 진입을 검사한다.
5. 새 게임, 세이브·로드와 soft reset 뒤 글꼴 재초기화를 확인한다.
6. 가능한 범위에서 여러 대사·이름·메뉴를 순회해 PLAN-004에 없던 글자가 표시되는지 확인한다.
7. 장시간 진행 또는 자동 반복으로 축소된 게임 풀의 누수·할당 실패·화면 손상을 감시한다.
8. 일반 BIOS 결과를 한글 BIOS 기준과 비교하고 스크린샷·로그를 최소 수량으로 보존한다.

실기 검증은 사용자가 실행 가능한 이미지가 완성된 다음 별도로 수행한다. 에뮬레이터 통과만으로 실기 호환을 단정하지 않는다.

### I. 정리와 보존 확인

- 에뮬레이터와 디버거를 종료한다.
- 보호된 입력과 최종 `current.bin`의 SHA-256을 기록한다.
- `work/fq4/rom/`의 전체 ROM BIN이 한 벌인지 확인한다.
- 임시 전체 ROM과 불필요한 로그·payload를 제거한다.
- 재현 명령, 변경 manifest와 검증 결과를 문서화한다.

## 6. 판정 기준

### 통과

다음을 모두 만족해야 한다.

1. 대상 `DUMMY.DUM` 섹터가 기존 게임에서 사용되지 않는다는 정적·실행 근거가 있다.
2. CD 읽기와 완료 대기 경로가 재현 가능하게 식별된다.
3. 전체 글꼴이 디스크에서 RAM으로 정확히 한 번 적재되고 해시가 일치한다.
4. 2,350개 조회, BIOS fallback, ABI와 오류 경로 검사가 통과한다.
5. EDC/ECC, ISO 구조, ROM 크기와 diff manifest가 모두 통과한다.
6. 일반 BIOS에서 기존 확인 문자열과 새 한글 문자열이 정상 표시된다.
7. 전투·맵 전환·세이브·로드·리셋 및 장시간 검사에서 메모리 문제가 없다.
8. 입력은 보존되고 전체 ROM은 `current.bin` 한 벌만 남는다.

### 부분 통과

구현·정적 검사와 일반 BIOS 기본 화면은 통과했지만 장시간 회귀 또는 실기 확인이 남으면 부분 통과로 기록한다. 확인하지 않은 범위를 성공으로 추정하지 않는다.

### 실패

- `DUMMY.DUM` 대상 영역의 사용 가능성을 배제하지 못한다.
- 안전한 CD 읽기·동기화 지점을 찾지 못한다.
- RAM 예약이 기존 할당이나 참조 영역과 충돌한다.
- 예상 밖 ROM 변경, EDC/ECC 오류 또는 ISO 손상이 발생한다.
- 일반 BIOS 표시나 기존 게임 진행이 손상된다.

실패하면 최초 실패 관문에서 ROM 쓰기를 중단하고 대체 구조를 완료 문서에 제안한다.
