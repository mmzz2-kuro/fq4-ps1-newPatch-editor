# FQ4-PLAN-016 — 부대 종족 제한 확장 선택 옵션 통합 계획

- 작성일: 2026-09-14
- 상태: **완료**
- 선행 결과: [FQ4-FINISH-015](../finish/015-party-race-limit-expansion.md)
- 보류 작업: PLAN-014 미래 xdelta 호환은 계속 보류
- 대상 GUI: `tools/fq4_bios_independent_gui.py`
- 대상 EXE: `tools/dist/FQ4-Standard-BIOS-Korean-Tool.exe`
- 완료 문서 예정: `docs/fq4/finish/016-optional-party-race-limit-gui.md`

## 1. 목적

PLAN-015에서 검증한 부대 종족 제한 확장을 기존 BIOS 독립 한글패치와 분리 가능한 선택 기능으로 정리한다.

종족 제한 변경 로직은 독립 모듈과 명령행 도구로 유지하고, 기존 GUI에는 기본값이 꺼진 체크박스를 추가한다. 사용자는 다음 두 결과 중 하나를 선택할 수 있다.

- 체크 해제: 기존 BIOS 독립 한글패치만 생성
- 체크 선택: BIOS 독립 한글패치 생성 후 부대 종족 그래픽 예산 제한 확장도 적용

이 구조는 제한 확장을 별도로 재사용할 수 있게 하면서도 일반 사용자가 한 GUI 안에서 선택해 적용할 수 있게 한다.

## 2. 표시할 기능의 정확한 의미

PLAN-015 분석 결과, 게임에는 고정된 `10종류` 배열 제한이 없었다. 서로 다른 종족을 처음 추가할 때 종족별 그래픽 비용을 한 번씩 합산하고, 원본은 합계가 `480` 미만일 때만 허용한다.

- 일반 종족 비용: 주로 `48`
- 일부 종족 비용: `32`
- 원본 판정: 합계 `< 480`
- 확장 판정: 합계 `< 865`
- 일반 비용 종족 18종의 합계: `864`

따라서 GUI에는 고정 종족 수를 보장하는 표현 대신 다음 의미가 드러나는 문구를 사용한다.

```text
부대 종족 제한을 18종 수준으로 확장 (실험적)
```

설명에는 종족별 그래픽 비용에 따라 실제 허용 수가 달라질 수 있고, 기본 동작은 확인됐지만 장시간 플레이 검증이 더 필요하다는 점을 표시한다.

## 3. 구현 범위

### A. 독립 패치 모듈

- `tools/scripts/build_party_race_limit_patch.py`의 핵심 변경을 재사용 가능한 함수로 정리한다.
- 파일 경로뿐 아니라 BIOS 독립 빌드 엔진이 생성 중인 결과에도 적용할 수 있게 한다.
- 8개 MIPS 비교 명령의 원래 값이 모두 `0x1E0`인지 검사한 뒤 `0x361`로 바꾼다.
- 예상하지 않은 값이나 이미 변경된 입력에는 조용히 중복 적용하지 않고 명확한 오류를 낸다.
- 독립 명령행 사용 방법은 계속 제공한다.

### B. 기존 빌드 엔진 옵션

- `tools/scripts/build_fq4_bios_independent.py`에 `--expand-party-species-limit` 선택 인자를 추가한다.
- 인자가 없으면 기존 처리 순서와 결과를 유지한다.
- 인자가 있으면 BIOS 독립 한글패치 적용 뒤, 최종 EDC/ECC 전수 복구와 검증 전에 종족 제한 변경을 적용한다.
- Python GUI와 frozen EXE가 같은 엔진 옵션을 사용하게 한다.

### C. GUI 체크박스

- 체크박스 기본값은 해제 상태로 둔다.
- 실행 중에는 다른 입력과 함께 체크박스를 잠그고, 완료·실패·취소 뒤 다시 활성화한다.
- 체크 상태를 작업 시작 시 한 번 고정하여 실행 도중 값이 바뀌지 않게 한다.
- 처리 결과와 로그에 제한 확장 적용 여부를 기록한다.
- 실험 기능 설명과 추가 플레이 테스트 필요성을 GUI 안에서 확인할 수 있게 한다.

### D. 단일 EXE 재빌드

- 기존 이름 `FQ4-Standard-BIOS-Korean-Tool.exe`로 원자적으로 교체한다.
- 날짜별 EXE나 전체 ROM 복사본을 추가로 쌓지 않는다.
- frozen 환경에서도 체크 해제와 선택 경로가 모두 같은 결과를 내는지 검사한다.

## 4. 출력 호환 기준

250826 한글패치 기반의 검증 입력에서 다음 결과를 기준으로 삼는다.

| 선택 | 예상 BIN SHA-256 | 의미 |
|---|---|---|
| 체크 해제 | `616ae2e0e44949b9217b94de336fc2e279e621e8753039d0a77818829f59c45d` | 기존 BIOS 독립 결과와 완전 동일 |
| 체크 선택 | `684d47b644f961b6552c311dffe577418f0b74ba109da7c6c25d57838beeba31` | PLAN-015 제한 확장 포함 결과 |

체크 해제 결과가 달라지면 기존 기능 회귀로 판정하고 EXE를 교체하지 않는다.

## 5. 검증 절차

### 엔진 검증

- 같은 검증 입력으로 체크 해제·선택 결과를 각각 한 번 생성한다.
- 두 결과의 SHA-256을 위 기준값과 비교한다.
- 체크 선택 결과에서 8개 비교 명령이 모두 `0x361`인지 확인한다.
- 체크 해제 결과에는 8개 비교 명령이 기존 `0x1E0`으로 남는지 확인한다.
- 잘못된 사전 값과 중복 적용을 거부하는지 검사한다.

### 디스크 검증

- 각 결과의 전체 43,002개 sector를 검사한다.
- sync, header, subheader, EDC, P와 Q 오류가 모두 0이어야 한다.
- CUE가 최종 BIN 이름과 `MODE2/2352`를 정확히 참조하는지 확인한다.

### GUI와 EXE 검증

- Python GUI와 단일 EXE에서 체크박스 기본값이 꺼져 있는지 확인한다.
- 두 실행 형태에서 체크 상태가 엔진 인자로 정확히 전달되는지 확인한다.
- 실행 중 중복 시작 방지, 취소, 오류 처리와 임시 파일 정리를 검사한다.
- GUI/EXE의 체크 해제·선택 결과가 명령행 엔진 결과와 각각 동일한지 확인한다.
- 사용자 확인이 끝난 PLAN-015 기본 동작을 보존하고, 추가 장시간 플레이 검증은 알려진 잔여 확인 항목으로 기록한다.

## 6. 원본 보존과 용량 규칙

- `original/`, `patched/`, `korean-patch/`와 BIOS는 읽기 전용으로 사용한다.
- 전체 작업 ROM은 `work/fq4/rom/current.bin` 한 개만 유지한다.
- 시험 출력은 한 번에 한 개의 임시 BIN/CUE만 만들고 해시·sector 검증 직후 제거한다.
- 실패나 취소 때 불완전한 출력과 임시 전체 ROM을 제거한다.
- 기존 사용자 출력 파일은 성공한 최종 결과가 준비된 뒤에만 원자적으로 교체한다.
- 분석·변환·검증 코드는 `tools/scripts/`, 사용자 GUI는 `tools/`에 둔다.

## 7. 통과 기준

- 종족 제한 변경이 독립 모듈·명령행 도구로 계속 사용 가능하다.
- GUI 체크박스는 기본 해제이며 사용자가 명시적으로 선택할 때만 제한 확장을 적용한다.
- 체크 해제 출력은 기존 BIOS 독립 결과와 바이트 단위로 동일하다.
- 체크 선택 출력은 사용자가 작동을 확인한 PLAN-015 결과와 바이트 단위로 동일하다.
- 두 출력 모두 전체 EDC/ECC와 CUE 검사를 통과한다.
- Python GUI와 frozen EXE의 동작과 결과가 일치한다.
- 원본 파일은 변경되지 않고 전체 ROM과 EXE 복사본이 누적되지 않는다.
