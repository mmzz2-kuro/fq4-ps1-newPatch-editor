# FQ4-PLAN-011 — 일반 BIOS용 한글 ROM 생성 GUI 계획

- 작성일: 2026-09-13
- 상태: **사용자 확인 대기**
- 선행 결과: [FQ4-FINISH-010](../finish/010-glyph-index-and-alignment-correction.md)
- 현재 검증 ROM SHA-256: `95bb338e4f836f37323b9011491f0fd7e376b31b4fc5514bccd6bf613f0df83e`
- GUI 위치: `tools/fq4_bios_independent_gui.py`
- 완료 문서 예정: `docs/fq4/finish/011-bios-independent-patch-gui.md`

## 1. 목적

명령행이나 에뮬레이터 디버깅 없이 사용자가 파일을 선택해 일반 PS1 BIOS와 실기에서 사용할 수 있는 퍼스트퀸4 한글 ROM을 생성하는 Windows GUI를 만든다.

GUI는 다음 입력을 받는다.

1. 퍼스트퀸4 일본판 원본 BIN
2. 기존 한글패치 xdelta
3. 한글 글꼴이 들어 있는 `SCPH1001.BIN`
4. 결과 BIN 저장 위치

처리가 완료되면 결과 BIN과 같은 이름의 CUE 한 벌을 만들고 검증 결과와 SHA-256을 표시한다.

## 2. 사용자 흐름

1. `원본 BIN`, `한글패치`, `한글 BIOS`, `출력 BIN`을 각각 선택한다.
2. GUI가 파일 크기와 SHA-256을 읽어 지원 여부를 표시한다.
3. `일반 BIOS용 ROM 만들기`를 누른다.
4. 기존 한글패치를 임시 출력 한 벌에 적용한다.
5. 검증된 전체 한글 글꼴 payload, CD loader와 lookup 훅을 적용한다.
6. Mode 2 Form 1 EDC 및 P/Q ECC, ISO 구조와 변경 범위를 검사한다.
7. 모든 검사가 통과한 경우에만 결과 BIN을 원자적으로 확정하고 CUE를 작성한다.
8. 성공 화면에 결과 경로, 크기, SHA-256과 일반 BIOS 사용 안내를 표시한다.

## 3. 지원 입력과 판정

- 현재 검증 기준은 일본판 원본 ROM과 `퍼스트퀸4 한글패치(250826).xdelta` 조합이다.
- 알려진 입력은 SHA-256으로 판정하고 파일명에는 의존하지 않는다.
- `241112`처럼 현재 제품 코드와 일치하지 않는 패치는 지원하지 않는 입력으로 명확히 표시한다.
- BIOS는 검증된 한글 BIOS의 크기와 SHA-256을 확인한다.
- BIN/CUE 트랙 형식은 `MODE2/2352`만 허용한다.
- 잘못된 입력에는 어느 파일이 일치하지 않는지 보여주며 출력 파일을 남기지 않는다.

## 4. 구현 구조

### GUI

- Python 표준 `tkinter`를 사용해 외부 GUI 의존성을 두지 않는다.
- 파일 선택, 상태 표시, 진행률, 로그, 실행·취소 버튼을 제공한다.
- 긴 해시·패치 작업은 worker thread에서 실행해 창이 멈추지 않게 한다.
- 오류는 사용자 메시지와 상세 로그로 나누어 표시한다.
- 사용자 화면에는 ROM 해킹 주소 같은 내부 구현 정보를 노출하지 않는다.

### 제품용 빌드 모듈

- GUI에서 분석 스크립트를 직접 호출하지 않고 제품용 변환 모듈을 `tools/scripts/`에 분리한다.
- 입력 경로와 출력 경로를 인자로 받고 workspace 고정 경로에 의존하지 않게 한다.
- PLAN-010에서 확정한 글꼴 시작점 `0x69D68`, 70,500바이트, sector `24184..24218`, loader와 lookup 코드를 사용한다.
- 동봉된 `xdelta.exe`가 있으면 사용하고, 없으면 위치를 안내한다.
- subprocess 인자는 배열로 전달하고 경로의 공백·한글을 지원한다.

## 5. 원본 보존과 용량 정책

- 모든 입력 파일은 읽기 전용으로 열며 직접 수정하지 않는다.
- 출력 BIN이 입력 BIN 또는 BIOS와 같은 경로면 실행을 차단한다.
- 전체 ROM 임시 파일은 출력 폴더에 한 개만 만들고 성공 시 최종 파일로 원자 교체한다.
- 실패·취소 시 임시 전체 ROM을 즉시 제거한다.
- 같은 출력이 이미 있으면 GUI에서 명시적으로 덮어쓰기를 확인한다.
- BIN을 성공적으로 만든 뒤 CUE만 추가하며 백업 BIN이나 날짜별 복사본을 만들지 않는다.
- 프로젝트 검증 중에는 기존 `work/fq4/rom/current.bin` 한 벌을 재사용하고 추가 전체 ROM을 보존하지 않는다.
- `original/`, `patched/`, `korean-patch/`의 파일은 수정하지 않는다.

## 6. 안전한 실패 처리

- 단계별 상태는 `입력 검사`, `한글패치 적용`, `일반 BIOS 변환`, `디스크 검증`, `완료`로 표시한다.
- 적용 전 예상 입력 해시와 실행 파일 훅의 원본 명령을 검사한다.
- 실행 파일 또는 DUMMY.DUM 구조가 다르면 쓰기를 중단한다.
- EDC/ECC, ISO 파일 목록, DUMMY.DUM extent, ROM 크기 또는 출력 해시가 예상과 다르면 실패 처리한다.
- 성공 전까지 최종 출력 경로에는 불완전한 BIN을 두지 않는다.
- 예외의 stack trace는 상세 로그에 기록하되 GUI는 복구 가능한 상태로 돌아간다.

## 7. 검증 계획

### 변환 엔진

- 검증된 원본+xdelta+BIOS 조합의 결과 SHA-256이 PLAN-010 ROM의 `95bb338e...f0df83e`와 일치해야 한다.
- 실행 파일 코드, 35개 글꼴 sector, EDC/ECC와 CUE 내용을 검사한다.
- `font_ready`, 2,350자 lookup과 대표 13자 변환을 격리 실행으로 검사한다.

### GUI

- 한글·공백이 포함된 입력 및 출력 경로를 검사한다.
- 누락 파일, 잘못된 ROM·패치·BIOS, 읽기 전용 출력 폴더와 기존 출력 파일을 검사한다.
- 처리 중 중복 실행 방지, 취소와 임시 파일 정리를 검사한다.
- 성공 시 BIN 한 개와 CUE 한 개만 생성되는지 확인한다.
- GUI를 닫았다 다시 실행해도 작업 ROM이나 임시 파일이 누적되지 않는지 확인한다.

### 최종 실행

- GUI 결과가 현재 검증 ROM과 byte 단위로 일치하는지 확인한다.
- 일반 BIOS DuckStation에서 cold boot와 한글 RAM 해시를 확인한다.
- 사용자가 지도 메뉴의 `시간경과`, `부대이동`, `탐색` 화면을 확인한다.

## 9. 통과 기준

- 지원 입력을 선택하면 PLAN-010과 동일한 BIN과 유효한 CUE가 생성된다.
- 입력은 수정되지 않고 실패·취소 후 임시 전체 ROM이 남지 않는다.
- 출력은 BIN 한 개와 CUE 한 개뿐이며 자동 백업을 만들지 않는다.
- 잘못된 입력과 출력 충돌을 GUI가 작업 전에 차단한다.
- 한글·공백 경로, 진행 상태와 오류 표시가 정상 작동한다.
- 일반 BIOS에서 전체 글꼴이 적재되고 정상 교정된 한글이 표시된다.
