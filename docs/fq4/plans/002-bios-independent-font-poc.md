## 1. 목표와 승인 범위

이번 작업의 목표는 동봉된 한글 BIOS를 사용하지 않고도, 패치 ROM에 저장한 한글 글리프가 게임의 기존 렌더링 경로를 통해 대표 화면에 표시될 수 있는지 증명하는 것이다.

이번 승인을 받으면 다음 범위까지만 수행한다.

- 250826 패치본을 고정 기준으로 삼아 대표 한글 문자열과 글리프 공급 경로를 검증한다.
- 필요한 글리프 자산, RAM 상주 위치, 디스크 저장 위치, 초기 적재 경로와 조회 훅을 설계한다.
- 대표 문자열에 필요한 최소 글리프 집합으로 개발용 PoC를 만든다.
- 일반 PS1 BIOS 환경에서 에뮬레이터 런타임 검증을 시도한다.
- 결과와 미해결 사항을 완료 문서에 기록한다.

전체 한글 글리프 이관, 전체 게임 텍스트 열거, 완제품 패처·GUI 제작, 배포용 패치 생성, 실기 지원 확정은 이번 승인 범위에 포함하지 않는다. PoC가 통과하면 각각 별도 계획과 사용자 확인을 거친다.

## 2. 고정 전제와 변경 금지 규칙

- `original/`, `patched/`, `korean-patch/`는 읽기 전용 입력이다. 이동·삭제·수정·덮어쓰지 않는다.
- 분석·변환·빌드 스크립트는 `tools/scripts/`에 작성한다. 사용자용 GUI가 필요해질 경우 `tools/`에 작성하되 이번 PoC에서는 만들지 않는다.
- 새 전체 ROM 복사본을 만들지 않는다. 기존 `work/fq4/rom/current.bin`을 250826 기준으로 검증한 뒤 같은 파일을 PoC 결과로 갱신한다.
- 반복 빌드마다 작업용 ROM을 먼저 보존 원본과 250826 xdelta에서 초기화하여 중복 패치 적용을 방지한다. 초기화와 PoC 쓰기는 하나의 빌드 명령에서 수행한다.
- 빌드 실패 시 부분 수정된 작업용 ROM을 성공 결과로 남기지 않는다. 가능한 경우 임시 파일이 아닌 메모리 또는 동일 작업 파일의 원자적 교체를 사용한다.
- ROM 이력은 별도 전체 이미지 백업 대신 입력·출력 해시, 예상 쓰기 목록, 스크립트와 재현 명령으로 남긴다.
- 동봉 BIOS 전체 또는 그 일부는 분석 입력으로만 취급한다. 배포 산출물에 BIOS 파일이나 추출 글리프를 포함하는 결정은 권리·배포 경계가 확정되기 전에는 하지 않는다.

## 3. 선행 분석에서 확정된 기준

- 게임은 실행 파일 `SLPS_006.04`를 `0x80010000`에 적재한다.
- 대표 글리프 경로는 `0x800464C0 → 0x80082C8C → BIOS B0(51h) → 0x80046674 → LoadImage`이다.
- `0x80046674`는 BIOS의 30바이트, 16×15 1bpp 글리프를 게임이 쓰는 128바이트, 16×16 4bpp 데이터로 변환한다.
- 대표 패치 문자열의 `8952 8EB5 917E`는 동봉 BIOS에서 “교섭중” 글리프로 확인되었다.
- 위 렌더링 경로는 원본·241112·250826 실행 파일에서 동일하다.
- 실행 파일 적재 끝 `0x80116000` 이후 RAM은 자동으로 빈 공간으로 간주할 수 없다.
- 실제 게임 화면, 일반 BIOS, 화면 전환 이후 자산 수명과 PS1 실기는 아직 검증하지 않았다.

## 4. PoC가 판별할 가설

### 핵심 가설

대표 문자열에 필요한 글리프를 디스크에서 안전한 RAM 영역으로 적재하고 `Krom2RawAdd` 호출 대신 해당 RAM 주소를 반환하면, 기존 변환·VRAM 업로드 경로를 그대로 사용하여 일반 BIOS에서도 같은 한글 픽셀을 표시할 수 있다.

### 통과

다음을 모두 만족할 때만 통과로 판정한다.

1. PoC 글리프의 저장 위치, 조회, 적재·변환, RAM 상주, VRAM 소비가 하나의 근거 사슬로 연결된다.
2. 일반 BIOS에서 대표 문자열의 “교섭중” 글리프가 의도한 위치와 모양으로 실제 게임 화면에 표시된다.
3. 한글 BIOS에서 관찰한 기준 화면과 비교하여 해당 글리프 픽셀이 같거나 사전에 선언한 동등성 조건을 만족한다.
4. 주변 UI, 문자열 전후 처리, 화면 진입·종료·재진입에서 깨짐이나 잔상이 없다.
5. 글리프가 필요한 동안 RAM 내용이 유지되고 화면 전환 또는 재초기화 경로에서 소실되지 않는다.
6. 작업용 이미지의 모든 변경 바이트가 사전 작성된 예상 쓰기 목록으로 설명되며 디스크 구조와 섹터 보호 필드 검증을 통과한다.
7. 동봉 한글 BIOS 없이도 동작하며, PoC 실행에 사용한 일반 BIOS의 식별 해시와 환경이 기록된다.

### 실패

다음 중 하나가 확인되면 현재 설계를 실패로 판정한다.

- 안전한 RAM 상주 범위를 확보할 수 없다.
- 디스크 자산을 필요한 시점에 적재할 수 없거나 적재가 오디오·입력·화면 상태를 훼손한다.
- 조회 훅의 ABI, 지연 슬롯, 반환 경로나 원래 BIOS 폴백을 안전하게 보존할 수 없다.
- 대표 화면이 다른 글리프 공급자 또는 호환되지 않는 렌더러를 사용한다.
- 일반 BIOS에서 글리프가 표시되지 않거나 전환 후 깨진다.
- 변경 범위, 참조, 섹터 무결성을 완전히 설명할 수 없다.

실패 시 화면별 수시 적재, 실행 파일 내 최소 글리프 포함, 다른 초기화 시점 또는 별도 로더 방식 중 첫 번째 원인에 대응하는 대안을 제시한다. 자동으로 다른 설계를 구현하지 않는다.

### 미해결

실행 환경이나 근거 부족으로 실제 소비를 판정하지 못하면 미해결이다. 정적 빌드 성공이나 격리 함수 성공을 런타임 통과로 기록하지 않는다. 마지막으로 확인된 경계와 첫 미확인 경계를 완료 문서에 남긴다.

## 5. 실행 계획

### A. PoC 기준과 대표 경로 고정

- 작업용 ROM이 250826 재현 해시 `9363cdfa247d38f5f819f5e79a25ff25ada3b2394f887726f29231da6ccbffb5`와 일치하는지 확인한다.
- 대표 문자열 `8952 8EB5 917E`와 이를 실제로 호출하는 화면·진입 조건을 정한다.
- 한글 BIOS 사용 기준 화면과 일반 BIOS 실패 화면을 같은 ROM, 에뮬레이터 버전, 설정과 진입 절차로 관찰한다.
- 필요한 상태에 접근할 수 없으면 세이브 상태를 검증의 시작점으로 사용하지 않고, 정상 진입 절차 또는 명시적인 상태 개입을 별도 근거로 구분한다.

산출물: PoC 기준 ID, 환경·BIOS 해시, 대표 화면과 재현 절차, 기준 캡처.

### B. 최소 글리프 자산과 매핑 확정

- PoC 범위는 `8952`, `8EB5`, `917E`와 대표 문자열에 필요한 공백·구두점으로 제한한다.
- 각 코드의 30바이트 글리프와 주소 계산을 동봉 BIOS에서 다시 검증한다.
- PoC 자산은 임시 개발 입력임을 명시한다. 전체 문자표나 배포용 폰트로 승격하지 않는다.
- 코드, 글리프 인덱스, 원본 BIOS 오프셋, 자산 내 오프셋을 기계 판독 가능한 매핑으로 작성한다.
- 알 수 없는 코드, 중복 매핑, 빈 글리프, 범위 초과는 빌드를 중단한다. 일반 BIOS 글리프가 필요한 코드는 원래 BIOS 경로로 폴백하도록 설계한다.

산출물: `docs/fq4/analysis/002/`의 PoC 매핑·자산 매니페스트 및 독립 디코더 검증.

### C. RAM 상주와 초기화 경로 결정

- 실행 파일, BSS, 힙, 스택, 전역 버퍼, 오버레이와 CD·GPU 관련 버퍼의 주소와 수명을 조사한다.
- 반복된 0바이트나 적재 끝 이후 영역만으로 빈 공간을 확정하지 않는다. 코드 참조, 초기화, 읽기·쓰기와 화면 전환 수명을 확인한다.
- 최소 글리프 데이터, 매핑표와 필요한 코드의 크기·정렬을 산정한다.
- 부팅 또는 글리프 초기화 경로 중 자산을 한 번 적재할 수 있는 시점을 찾고, 재진입·초기화·화면 전환 후 유지 조건을 정한다.
- 안전한 상주 영역이 없으면 이 설계를 실패로 기록하고 수시 적재 대안의 비용과 위험을 제시한다.

산출물: 후보별 RAM 범위, 근거, 수명, 충돌 위험 및 채택·기각 판정.

### D. 디스크 저장·적재 경로 결정

- 기존 파일 내부의 검증된 여유 공간, 새 파일, 실행 파일 포함 방식의 후보를 비교한다.
- 빈 섹터나 패딩은 참조·로더·파일시스템 소비가 배제된 경우에만 사용한다.
- 새 CD 읽기가 필요하면 호출 시점의 CD 모드, Form, 대상 버퍼, IRQ/DMA, XA·CDDA·동영상 스트리밍과 복귀 상태를 확인한다.
- PoC에서는 최소 변경으로 대표 경로를 증명할 저장 방식을 선택하되, 후속 전체 글리프 확장 가능성과 제한을 기록한다.
- ISO 파일 크기·extent·LBA 또는 게임 고유 메타데이터가 바뀌면 모든 양방향 필드와 참조를 갱신하고 검증한다.

산출물: 저장 위치, 적재 명령·시점, RAM 목적지와 영향을 받는 디스크 메타데이터.

### E. 조회 훅과 빌드 도구 작성

- `0x80082C8C`의 BIOS 호출 래퍼 또는 그 상위 호출부 중 영향이 가장 명확한 지점을 선택한다.
- PoC 코드이면 RAM 글리프 주소를 반환하고, 그 외 코드는 원래 BIOS B0(51h) 동작을 보존한다.
- 훅의 입력 레지스터, 반환 레지스터, 스택·저장 레지스터, 원래 명령, 분기와 지연 슬롯, 모든 반환 경로를 명세한다.
- 실행 파일 변경 전 기준 해시와 대상 원본 바이트를 검사한다. 예상과 다르면 쓰지 않고 실패한다.
- MIPS R3000A 호환 프로필로 생성 코드의 어셈블·역어셈블을 같은 의미 모델에서 확인하고, 최종 배치 후 명령 경계·분기 목적지·지연 슬롯을 다시 검사한다.
- 모든 자산·코드·포인터·메타데이터 변경을 하나의 예상 쓰기 계획으로 먼저 계산한다. 겹치는 쓰기, 보호 범위, 설명되지 않는 최종 차이가 있으면 빌드를 중단한다.
- `tools/scripts/`에 하나의 PoC 빌드 진입점을 작성하여 보존 원본 → 250826 패치 → PoC 작업용 ROM을 재현한다.

산출물: 훅 명세, 예상 쓰기 매니페스트, 재현 가능한 PoC 빌드 스크립트.

### F. 정적·격리 검증

- 수정하지 않은 입력으로 분석·추출·재삽입 경계의 무변경 왕복 또는 사전 선언한 동등성을 확인한다.
- 글리프 조회 함수를 유효 PoC 코드와 일반 코드, 경계·무효 코드로 격리 실행한다.
- 반환 주소가 선언된 RAM 글리프 경계만 가리키며 일반 코드는 원래 BIOS 결과를 유지하는지 확인한다.
- 글리프 변환 결과가 동봉 한글 BIOS 기준의 128바이트 데이터와 일치하는지 독립적으로 비교한다.
- 최종 ROM의 크기, CUE, ISO 레코드, 변경 파일·섹터, Mode 2 Form, EDC/ECC를 확인한다.
- 최종 diff의 모든 변경 바이트가 예상 쓰기에 포함되고 입력 해시가 보존되는지 확인한다.

산출물: 정적 검증 보고서, 격리 실행 벡터, 최종 diff 감사 결과.

### G. 에뮬레이터 런타임 검증

- 일반 BIOS로 새 부팅하여 자산 적재 경계를 실제로 통과한다. 적재 이후 생성된 다른 버전의 세이브 상태로 이를 대신하지 않는다.
- 대표 화면에서 의도한 글리프의 위치·모양, 주변 UI, 문자열 진행을 확인한다.
- 화면 종료·재진입과 관련 상태 전환 후 글리프 RAM 내용과 표시가 유지되는지 확인한다.
- 가능하면 한글 BIOS 기준 화면과 픽셀 비교를 수행하되 캡처 조건 차이와 허용 오차를 기록한다.
- 실패 시 저장 → 조회 → 적재/변환 → 상주 → 소비 중 첫 번째 끊어진 경계를 찾아 기록한다.
- 이용 가능한 에뮬레이터나 일반 BIOS가 없어 검증할 수 없다면 정적 완료와 런타임 미해결을 구분한다. 임의로 BIOS를 내려받지 않는다.

산출물: 정확한 ROM·BIOS·에뮬레이터 식별, 진입 절차, 캡처·로그 및 판정.

### H. 결론과 완료 문서

## 7. 작업 중 중단·재계획 조건

다음 상황에서는 구현을 억지로 계속하지 않고 근거를 정리한 뒤 계획 변경 여부를 사용자에게 제시한다.

- 대표 화면이 조사한 렌더러를 사용하지 않는 경우.
- 안전한 RAM 또는 적재 시점을 확정할 수 없는 경우.
- 250826 실행 파일의 대상 바이트가 분석 기준과 다른 경우.
- 필요한 변경이 최소 PoC를 넘어 전체 파일 재배치, 복잡한 CD 상태 변경 또는 별도 오버레이 설계로 확대되는 경우.
- 동봉 BIOS에서 추출한 자산의 사용·배포 조건이 PoC 이후 제품 설계를 바꾸는 경우.
- 일반 BIOS에서 정적·격리 검증과 충돌하는 런타임 결과가 나오는 경우.

## 8. 완료 기준

이번 작업은 다음이 모두 기록되면 종료한다. 기술적 결과는 통과·실패·미해결 중 하나로 명시한다.

1. 250826 기준과 대표 화면·문자·렌더러가 고정되어 있다.
2. 최소 글리프의 코드→자산→RAM 주소 매핑이 가역적으로 검증되어 있다.
3. RAM 위치와 수명, 디스크 저장과 적재 경로가 근거로 설명되어 있다.
4. 훅 ABI·원래 동작·분기·지연 슬롯과 최종 명령열이 검증되어 있다.
5. 변경 바이트 전체가 예상 쓰기로 설명되고 이미지·섹터 무결성 검사를 통과하거나 실패 원인이 기록되어 있다.
6. 일반 BIOS의 실제 게임 화면에서 통과 기준을 검증했거나, 첫 미확인 경계와 필요한 사용자 관찰이 명확하다.
7. 모든 입력 파일의 종료 해시가 시작 기준과 일치한다.
8. 작업용 전체 ROM이 `work/fq4/rom/current.bin` 한 벌뿐임을 확인한다.
9. 완료 문서에 지원되는 주장, 지원되지 않는 주장과 다음 권장 계획이 기록되어 있다.
