# PLAN-017 PS1 세이브 구조 분석

분석 대상은 `BISLPS-00604-1`, `BISLPS-00604-2` 두 세이브가 든 128KiB raw PS1 메모리카드다. 각 세이브는 4개 블록, 총 32KiB이며 게임 내부 헤더는 `SC 13 04`이다.

게임 로더 분석 결과, payload `0x09A6`부터 32바이트 크기의 캐릭터 레코드 640개가 런타임 `0x8009EB80`으로 복사된다. CLASS는 레코드 `+0x0C`의 1바이트 값이다. 부대 그래픽 예산 검사 함수도 `0x8009EB8C + 캐릭터 바이트 오프셋`에서 이 값을 읽으므로 CLASS 필드는 실행 코드로 교차 확인됐다.

에디터가 제공하는 필드는 다음과 같다.

| 레코드 위치 | 형식 | 표시 |
|---|---|---|
| `+0x00` | LE uint16 | FT |
| `+0x02` | LE uint16 | 이름 ID |
| `+0x0C` | uint8 | CLASS ID |
| `+0x18` | uint8 | LV |
| `+0x19` | uint8 | HR |
| `+0x1A` | LE uint16 | HP |
| `+0x1C` | uint8 | AT |
| `+0x1D` | uint8 | AR |
| `+0x1E` | uint8 | DF |
| `+0x1F` | uint8 | DR |

> PLAN-022 정정: CLASS 이름표와 그래픽의 유효 범위는 ID 0~219이다. 기존 0~149 제한은 CLASS 150~219 캐릭터를 숨기는 원인이었으며 세이브 에디터에서 수정했다.

CLASS 표는 ID 0~219 전체를 지원한다. 캐릭터 이름은 ROM의 640개 고정 이름표를 세이브 레코드의 이름 ID와 연결한다. 저장 목록은 실제 HP(`+0x1A`)가 0보다 크고 이름·CLASS ID가 유효한 레코드를 표시한다.

사용자가 제공한 2번 슬롯 명단 화면과 대조해 아레스, 알프레드, RADICAL, SHAKEY, CARL, YULIA, MILAN, INDY, AEOLUS, SAMSON, SEAN, DAN의 이름·CLASS·LV·HP·HR·AT·AR·DF·DR가 모두 일치함을 확인했다. 이 교차 검증으로 기존 구현에서 `+0x02`를 HP로 잘못 해석하고 CLASS를 몬스터 종족명 일부로 표시한 오류를 바로잡았다. 2번 슬롯에서 표시되는 유효 레코드는 419개다.

내부 체크섬 8바이트는 payload `0x7DA6`에 있다. 계산할 때 이 8바이트를 모두 0으로 만든 다음, 32KiB payload의 각 4KiB 페이지를 XOR해 각 페이지 결과를 순서대로 저장한다. PS1 카드 디렉터리 entry의 체크섬은 앞 127바이트 XOR이며, payload만 편집하므로 디렉터리는 그대로 유지한다.

통제 시험에서는 슬롯 1의 레코드 229를 MIMIC(9)에서 BALESTA(10)로 바꿨다. 전체 128KiB 카드에서 달라진 것은 종족 바이트 `0x4652`와 해당 페이지 체크섬 `0x9DA8`뿐이었다. 시험 파일은 누적 복사본을 만들지 않고 `work/fq4/save-editor/current-test.mcd` 하나로 유지한다.

게임 내 로드 후 외형·전투·재저장 확인은 사용자 플레이 검증 항목으로 남아 있다. 구조, 변경 범위, 체크섬과 독립 EXE 실행은 자동 검증했다.
