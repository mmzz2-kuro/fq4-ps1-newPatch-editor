# PLAN-015 부대 종족 제한 분석

## 결론

알려진 “한 부대 10종류”는 고정 개수 비교가 아니다. `0x80072A04`는 부대원과 새로 들어올 캐릭터의 종족 ID를 읽고, 중복 종족은 한 번만 계산한다. 각 종족의 3바이트 그래픽 계수를 곱한 비용을 합산한 뒤 원본은 `합계 < 480`을 요구한다.

- 대부분의 종족 비용: `2 × 2 × 12 = 48`
- 일부 종족 비용: `2 × 2 × 8 = 32`
- 일반 비용 종족만 구성할 때 원본 허용 범위: 9종(`432`)
- 비용 32 종족이 섞이면 10종 이상도 가능

따라서 실제 제약은 “종족 10개 배열”이 아니라 전투 그래픽 적재 예산이다. 한국어 공략의 10종 설명은 대표적인 체감 상한으로 볼 수 있으나 모든 조합에 적용되는 정확한 값은 아니다. 온라인 공략에도 한 부대에 10종족만 가능하다는 설명이 있으나, 실행 코드가 더 정확한 판정 근거다.

## 변경

일반 비용 종족 18개의 합계는 `18 × 48 = 864`다. 기존 비교의 의미를 유지하면서 864를 포함하도록 상한을 `합계 < 865(0x361)`로 변경했다.

같은 예산을 검사하는 8개 지점을 모두 변경했다.

| RAM 주소 | 역할 |
|---|---|
| `0x80017F58` | 캐릭터/부대 구성 검사 |
| `0x8001832C` | 캐릭터/부대 구성 검사 |
| `0x80020A70` | 캐릭터/부대 구성 검사 |
| `0x80064F2C` | 그래픽 적재 전 검사 |
| `0x80065874` | 그래픽 적재 전 검사 |
| `0x80065F04` | 그래픽 적재 전 검사 |
| `0x8006B27C` | 전투/부대 그래픽 구성 검사 |
| `0x80072C28` | 이동·편성 검증 함수의 최종 판정 |

부대 구조체는 인원 수와 각 캐릭터 ID를 보존하며, 별도의 10칸 종족 목록을 저장하지 않는다. 세이브 형식 변경은 필요하지 않다.

## 확인된 거부 문구

- `種類が多いため移動できません` — 종류가 많아 이동할 수 없음
- `種類が多すぎるため、このチーム内では馬に乗れません` — 종류가 너무 많아 현재 부대에서 승마 불가
- `種類が多すぎるので、別のチームにしてから来てください` — 종류가 너무 많으므로 다른 부대로 편성 후 재시도

## 검증 범위

- 9, 10, 11, 17, 18개의 일반 비용 종족이 새 상한에서 허용됨을 계산 검증했다.
- 콜드 부팅 RAM에서 초기 상주 코드 3곳의 새 명령어 적재를 확인했다.
- 일반 BIOS 전체 한글 글꼴은 `ready=1`, 기준 SHA-256 일치로 확인했다.
- 전체 43,002 raw sector의 sync/header/subheader/EDC/P/Q 오류는 모두 0이다.
- 실제 게임에서 자연스럽게 18종 부대를 구성해 전투 애니메이션까지 보는 검사는 사용자 플레이 확인 항목이다. 이 확인 전에는 18종 전투의 화면·VRAM 안정성을 완전 검증했다고 보지 않는다.
